# 실제 입력 시험 후 보완 검증

기준 버전은 `f51d47f2c8bcb09ed0fa34642e198f5bea336da9`다. 아래 결과는 수정 코드의 로컬 검증이며 새 버전의 실제 카메라 재시험 통과를 뜻하지 않는다.

| 문제 | 변경 | 확인 범위 |
| --- | --- | --- |
| 참고 카메라 프레임이 먼저 도착하면 주 카메라가 즉시 중단됨 | 첫 주 카메라 프레임도 기존 20초 대기 기준 적용 | 실제 요청 순서로 재현, 시작·종료·시간 초과 회귀 |
| 구역 판정을 잠시 얻지 못한 관측이 사건을 분리할 수 있음 | 기존 범위를 보존하고 해당 관측은 불명으로 처리 | 장시간 불명·후보 만료·새 관측 자격·이탈 정리·기존 무범위 입력; 실제 정상 구역 변경은 계속 분리 |

| 연속 사건의 검토 차단 안내가 비어 있고 보류 버튼이 활성화됨 | 서버의 세 차단 상태를 설명하고 보류·기존 선택의 제출도 차단 | 실제 화면 결함 확인 후 HTTP 대역 브라우저 7개 통과 |

모델, PPE 정책, 카메라별 임계값, 관측된 위반 시작·종료 시각, 20ms 연속성 기준과 개인정보 처리 기준은 바꾸지 않는다. DB 스키마는 36 그대로이며 새 FPS 값은 기존 Start JSON에 저장한다. 필드가 없는 기존 사건과 재시도 바이트는 유지한다. 새 추론 실행기는 새 API와 함께 배포해야 한다.

통합 코드에서 Python 회귀 211개, 브라우저 7개, frontend build·lint가 통과했다. 각 보완과 합본은 별도로 검토했다. 출력 경계의 상세 근거와 한계는 [프레임 경계 계약](../20261116_Capture_Output_Grid_Contract.md)에 기록했다.

남은 실측 항목:

- 주 카메라 1의 36→37번 청크 사이 72ms 시각 간격은 원인 확인 중이다. 허용 기준을 늘리거나 원본 시각을 덮어쓰지 않았다.
- 기존 카메라 2의 10개 후보는 계속 검토 대기이며 불완전 증거 상태다. 구역 변경으로 끝난 8건의 실제 원인은 새 방어 코드만으로 확정하지 않는다.
- 다음 실제 입력에서 두 카메라 지속 추론, 정상 사건 종료·영상 완성, 수동 판정·통계 반영, 규칙 자동 확정과 번복을 단계별로 다시 확인해야 한다.
- 이번 수정은 과거 불완전 영상을 복구하지 않으며, 장기 실행용 시각 검증 자동 갱신은 포함하지 않는다.
