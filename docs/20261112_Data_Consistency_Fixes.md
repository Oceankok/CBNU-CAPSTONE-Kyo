# 이벤트 검토·통계 정합성 보완

## 검토 및 오탐 집계

재검토 가능 여부는 API의 사전 검사뿐 아니라 DB 쓰기 트랜잭션 안에서 다시 확인한다. 보류/검토 불가 또는 2차 검토 대상만 재검토할 수 있다는 기존 정책을 유지하며, 다른 요청이 최종 판정을 마친 사건은 409로 거절한다. 검토가 계속 보류/2차 검토 대상인 상태의 편집 충돌까지 해결하는 클라이언트 버전 계약은 이번 변경에 포함하지 않는다.

오탐 집계는 재검토 횟수가 아니라 현재 남아 있는 사건의 최종 `event_status=false_positive` 건수를 기준으로 한다. 오탐→오탐 재검토는 증가시키지 않으며, 오탐↔확정/보류 전환 시 사건의 고정된 구역·분기·PPE 범위를 다시 집계한다. 검토와 집계 변경은 같은 쓰기 트랜잭션에서 처리하고, 명시적 사건 삭제 함수도 해당 범위를 갱신한다. 사건과 검토 이력 자체를 기준 자료로 사용하므로 별도의 중복 기여 원장을 추가하지 않는다.

사용자는 기존 자료가 테스트 사건임을 확인하고 v22 이관 시 현재 남은 사건 기준의 재계산을 승인했다. 따라서 과거 중복 집계와 이미 삭제된 테스트 사건의 기여는 제거한다. 이 정책은 실제 운영의 삭제 사건 누적 통계를 복원하는 기능이 아니다. 검토 이력·교육 자료는 보존하며 기존 분기 summary의 오탐 수만 바로잡는다. 오탐 외 통계 캐시는 일반 통계 갱신 시 다시 계산된다.

구역이 없는 카메라의 오탐·통계·추천 캐시는 기존 이벤트 summary와 동일하게 빈 구역 키를 사용한다. 실제 이벤트의 구역은 NULL을 유지하고, 추천 주제에는 '구역 미지정'을 표시한다. 이를 실제 작업자 배정 구역으로 간주하지 않는다.

## 통계 스냅샷

통계 및 추천 생성·조회는 하나의 트랜잭션 스냅샷 안에서 계산하고 응답까지 구성한다. 생성 후 별도 connection으로 다시 조회하지 않는다. SQLite는 생성 시 `BEGIN IMMEDIATE`, 조회 시 `BEGIN`을 사용한다. PostgreSQL은 첫 데이터 조회 전에 REPEATABLE READ를 설정하며, 쓰기는 기존 advisory lock과 함께 사용한다. 추천 단독 생성은 기존 분기 summary의 값이 바뀌지 않는 UPDATE를 통해 동시 최초 생성의 오래된 스냅샷도 직렬화 충돌로 감지한다.

PostgreSQL의 SQLSTATE 40001은 새 connection으로 전체 트랜잭션을 최대 3회 재시도한다. commit 실패도 재시도 범위에 포함하며 일반 무결성 오류는 재시도하지 않는다. 실제 PostgreSQL 환경에서 동시성 테스트를 실행한 뒤 배포해야 한다.

## 스키마 v20 → v21: 구역 스냅샷

`event_zone_snapshot`에 사건별 구역과 저장 시각·근거를 보존한다.

- 기존 사건: 이관 시 현재 카메라 구역을 고정하고 `source=migration_current`로 기록한다. 이는 사용자가 승인한 이관 정책이며, 과거 발생 당시 구역을 복원했다는 의미가 아니다.
- 새 사건: DB INSERT 트리거가 등록 시점 카메라 구역을 저장하며 `source=registered_current`로 기록한다.
- NULL 구역도 그대로 고정한다. 나중에 카메라를 배정해도 과거 미배정 사건을 소급 변경하지 않는다.
- 목록·필터·요약·분기 통계·추천·새 오탐 집계는 사건 구역 스냅샷을 사용한다. 카메라 자체의 현재 구역 조회는 기존대로 유지한다.
- 재실행 시 기존 스냅샷을 덮어쓰지 않으며 사건·검토·교육 자료를 삭제하지 않는다. 사건이 명시적으로 삭제되는 경우 해당 스냅샷만 FK로 함께 제거한다.

이 변경은 카메라 구역 변경이력을 도입하지 않는다. 구역 이동 전에 촬영한 영상이 이동 후 늦게 등록되면 등록 시점 구역으로 기록된다. 정확한 촬영시점 귀속에는 설정 버전 또는 변경이력이 추가로 필요하다.

SQLite와 PostgreSQL 초기화 경로 모두 v21 이관을 제공한다. 운영에서는 기존 데이터 백업과 쓰기 중단 후 이관해야 하며, 이번 작업에서 실제 사용자 DB·서버에는 적용하지 않았다.

## 스키마 v21 → v22: 테스트 오탐 집계 재정리

v21 구역 스냅샷을 사용해 현재 남아 있는 오탐 사건을 분기·구역·PPE별로 다시 집계한다. 집계 식별자는 범위의 해시로 만들므로 공백/밑줄이 다른 구역 이름이 동일 ID에 합쳐지지 않는다. 이관과 버전 갱신은 하나의 트랜잭션이며 재실행 시 v22 재정리를 반복하지 않는다. 기존 사건·검토·교육 자료를 삭제하거나 원본 영상을 건드리지 않는다.
