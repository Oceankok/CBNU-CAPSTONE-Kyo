# AI 추론 프로세스와 백엔드 연동 보완

## 실행 모드

기본 실행은 이벤트와 방송을 생성하지 않습니다. 추론 중에는 기존 `inference-load` API에 우선 신호를 보내며, 청크 경계에서 해제하고 `--poll` 시간만큼 대기합니다. 임대는 30초이고 프레임 경계에서 10초 간격으로 갱신합니다. 단일 추론 호출이 30초를 넘는 경우에는 TTL이 만료될 수 있으므로 실제 모델 통합 시 처리 시간을 확인해야 합니다.

```powershell
# 서버 PC의 프로젝트 루트에서 실행합니다.
# PPE_SERVER_URL과 처리 node 토큰 PPE_PROCESSING_NODE_TOKEN은 로컬에서 설정합니다.
python -m inference_worker.run_server --camera-id CAM_001 --max-chunks 30
```

`--submit-events`를 추가하면 검증을 통과한 후보와 완전한 클립만 서버로 전달합니다. 서버 이벤트 등록은 방송 명령을 만들 수 있으므로, 실제 방송 준비 후 사용합니다. 토큰은 관리자 로그인 토큰이 아니라 활성화된 처리 node 토큰을 사용합니다.

**현재 기본 모델의 후보에는 `verified_ppe_confidence`가 없습니다. 따라서 옵션을 켜도 기본 후보의 이벤트 전송은 차단됩니다.** 사람 탐지 신뢰도를 PPE 위반 신뢰도로 대입하지 않습니다. AI 담당자가 미착용 판정 기준과 실제 모델 버전을 확정하고 후보 생성부에 반영해야 합니다. 이 변경에는 모델 학습·Tracking 개선이나 판정 우회 기능이 포함되지 않습니다.

## 시작·재시작 시 영상 범위

기본 모드는 스트림을 처음 선택한 시점의 `last_sequence`를 시작 경계로 사용하며, 이미 서버 버퍼에 쌓인 청크는 건너뜁니다. 같은 스트림으로 재시작해도 과거 영상을 다시 판정하여 새 이벤트 ID와 방송을 만드는 일을 피합니다. 스트림이 교체되면 새 스트림의 시작 경계를 다시 설정합니다. 이후 조회마다 최신 위치로 이동하지 않으므로 실행 중 도착한 청크는 순서대로 처리합니다.

이것은 중단 없는 복구나 동일 사건 자동 병합이 아닙니다. 중단 이전 영상·추적 상태·미완성 클립은 복원하지 않으며, 재시작 후 새 영상에서 지속 관찰된 위반은 새 사건이 될 수 있습니다. 다시 시작한 직후에는 위반 지속시간과 사전 클립 구간을 새로 확보해야 합니다. `--max-chunks`는 기본 5개 처리 후 종료하는 점검 설정이므로 시연 실행 시 필요한 처리 수를 명시해야 합니다.

기존 버퍼를 분석하려면 `--replay-buffer`를 명시합니다. 이 옵션은 점검 전용이며 `--submit-events`와 함께 사용하면 모델·HTTP 클라이언트를 시작하기 전에 종료합니다. 다음 실행은 서버의 기존 버퍼를 읽지만 이벤트나 방송을 생성하지 않습니다.

```powershell
python -m inference_worker.run_server --camera-id CAM_001 --max-chunks 30 --replay-buffer
```

## 전달·정리 흐름

1. 검증된 후보에 이벤트 ID를 한 번 부여하고 후속 영상 대기 작업과 연결합니다.
2. 전후 2초의 영상이 모두 확보됐는지 검사합니다. 부족하면 이벤트를 전송하지 않습니다.
3. 임시 MP4를 생성한 후 기존 이벤트 API와 클립 업로드 API를 호출합니다. 같은 카메라의 `clip` 요청만 처리하며 다른 카메라의 `reference` 요청은 대신 채우지 않습니다.
4. 통신 오류와 일시적 429/5xx에 한해 최대 3회 재시도하며 이벤트 ID·본문·클립 요청 ID를 유지합니다.
5. 업로드 응답 유실 후 409가 발생하면 해당 요청이 실제로 `received`인지 조회합니다. 확인되지 않은 충돌은 성공 처리하지 않습니다.
6. 성공·실패 및 정상 종료 시 임시 원본 클립을 삭제합니다. 재시도 한도를 넘으면 오류를 반환하고 종료합니다. 디스크 기반 장기 재전송 큐는 추가하지 않습니다.

원본은 운영 검토 화면에 제공하지 않습니다. 운영체제 강제 종료·전원 차단 시에는 Python의 임시 폴더 정리가 실행되지 않을 수 있습니다. 기존 실행에서 남긴 `inference_worker/test_chunks` 파일은 이 변경으로 자동 삭제하지 않습니다.

## 검증

```powershell
python -m unittest discover -s inference_worker -t . -v
python -m unittest discover -s backend -t . -v
```

추론 테스트는 임시 DB, 합성 프레임, 가짜 탐지 결과와 저장소의 인물 없는 테스트 MP4를 사용합니다. 실제 HTTP 클라이언트를 테스트용 FastAPI에 연결하여 인증, 이벤트 저장, MP4 접수, 응답 유실 후 재시도와 중복 방지를 확인합니다. 실제 서버·GPU·모델·스피커·외부 API는 사용하지 않습니다.

CI의 SQLite 및 PostgreSQL 작업에서 두 테스트 모음을 실행합니다. 실환경에서 남은 검증은 실제 모델 후보 생성, 서버 청크 소비, 이벤트 등록, 비식별화 완료, 관리자 게시, 현장 방송까지의 전체 연동입니다.
