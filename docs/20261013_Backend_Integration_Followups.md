# 방송·시연·GPU worker 연동 보완

관련 이슈: #135, #136, #137. #138 자동 이벤트 병합은 이번 변경에 포함하지 않습니다.

## 방송 언어 선택

현장 PC의 `ko-KR`, `en-US`와 템플릿의 `ko`, `en`을 연결합니다. 특정 구역을 전체 구역보다 우선하고, 각 구역 안에서 정확한 locale → 기본 언어 순으로 탐색합니다. 대소문자 및 `_`/`-` 차이를 정규화합니다. 다른 언어로 임의 전환하지 않으며 일치하는 템플릿이 없으면 기존 `template_not_found` 결과를 유지합니다.

방송 명령에는 기존 현장 PC의 locale과 voice 설정을 그대로 전달합니다. 격리 테스트에서 이벤트 → 명령 생성 → 현장 명령 수신·실행 흐름을 확인하며 실제 스피커 출력은 별도 통합 확인 대상입니다.

## 실시간 추론 우선 신호

서버 PC의 AI 추론 프로세스가 다음 API를 호출합니다. 관리자 로그인 토큰이 아니라 관리자에게 처리 권한을 부여받은 **서버 처리 node 토큰**을 사용합니다.

| API | 용도 |
| --- | --- |
| `PUT /api/processing/inference-load` | `{"busy":true,"ttl_seconds":10}`로 추론 우선 구간 시작/갱신 |
| `PUT /api/processing/inference-load` | `{"busy":false}`로 우선 구간 종료 |
| `GET /api/processing/inference-load` | 서버 전체 신호의 `busy`, `busy_until` 조회 |

TTL은 1~30초입니다. 추론이 계속되는 경우 TTL 전에 갱신하고 종료 시 `busy:false`를 전송합니다. 프로세스가 종료되더라도 TTL 이후 해제됩니다. 현재 서버 PC의 단일 GPU를 공유하는 구조를 기준으로 합니다.

busy 동안 새 비식별화 작업을 배정하지 않습니다. 실행 중인 worker는 모델 초기화·얼굴 탐지·영상 프레임 처리의 경계에서 신호를 조회하고 대기하며 lease는 계속 갱신합니다. 이미 실행한 GPU 연산을 강제로 중단하거나 GPU 메모리를 반환하는 기능은 아닙니다. 실제 AI 프로세스의 신호 호출 연결 및 추론 지연 측정은 #139 통합 작업에서 확인합니다. 짧은 추론 배치 사이에 유휴 구간을 제공해야 비식별화 작업도 진행할 수 있습니다.

## 서버 클립 접수

API는 `PPE_PROCESSING_MODE=remote`로 실행하고 네이티브 GPU worker를 별도 프로세스로 실행합니다.

1. 기존 이벤트 생성 API로 이벤트를 등록합니다.
2. 처리 node 토큰으로 `POST /api/processing/events/{event_id}/clip-requests`에 `{"camera_id":"CAM_001"}`를 보내 `request_id`를 받습니다.
3. 확보한 MP4를 **multipart가 아닌 요청 본문**으로 `POST /api/processing/events/{event_id}/clip?request_id=...&camera_id=CAM_001&redaction_mode=scrfd`에 보냅니다.
4. 응답의 `media_id`, `job_id`, `clip_request_id`, `processing_state`로 접수 결과를 확인합니다. 요청은 `received`, 작업은 `queued`로 연결됩니다.
5. worker가 원본 수신 → 비식별화 → 결과 게시 → 로컬 임시 파일 정리 확인을 진행합니다. 완료된 비식별 미디어만 검토 화면에 제공됩니다.

이벤트·카메라·클립 요청의 일치를 검증합니다. 같은 요청의 중복 접수는 409로 거부합니다. 참고 카메라 영상은 해당 카메라를 지정하여 별도 클립 요청을 등록합니다. 영상 송신 방식 선택과 서버 클립 버퍼 구성은 AI/시스템 통합 담당 범위이며 이 API는 완성된 이벤트 클립 접수 경계입니다.

## 실패 및 정리

worker의 lease 만료는 실패 상태로 전환됩니다. 원본이 유효하고 기존 재처리 조건을 만족하면 관리자 재처리 API로 새 작업을 생성할 수 있습니다. 자동 무제한 재시도는 하지 않습니다. 클립 접수 자체가 실패한 요청은 새 요청을 등록하여 다시 접수합니다.

보관 삭제 결정은 진행 중 작업을 취소하며 늦게 도착한 결과를 게시하지 않습니다. worker의 원본·변환 파일 정리 확인과 기존 maintenance 재시도를 유지합니다. 공개 저장소에 원본이나 동의서 파일을 추가하지 않습니다.

## 시연 및 통합 확인

GPU 없는 시연 데이터는 [시연 데이터 실행 문서](20261013_Demo_Seed_Setup.md)를 따릅니다. 해당 데이터는 정상 미디어 검증과 리뷰 제약을 해제하지 않습니다.

백엔드 격리 테스트는 방송 locale 선택, 가짜 음성 출력, 시연 생성·초기화·리뷰, 추론 우선 신호 만료, 클립 접수·중복 차단을 확인합니다. 실제 영상 송출 → 서버 추론 → 클립 생성 → 비식별화 → 현장 방송의 전체 장치 연동은 별도 시연 검증이 필요합니다. 상용 VLM 장비 후보 인식은 이 GPU worker 변경으로 활성화하지 않습니다.
