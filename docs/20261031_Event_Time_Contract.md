# 이벤트 시각과 한국 날짜·분기 계약

## 저장·응답·집계

새 처리 이벤트는 UTC 오프셋이 명시된 ISO 8601을 DB에 저장합니다. 예: `2030-03-31T16:00:00.000000+00:00`. 일반 이벤트 조회 응답은 동일 순간을 한국 시각으로 반환합니다. 예: `2030-04-01T01:00:00.000000+09:00`. API는 오프셋을 제거하지 않습니다. 로컬 후보 생성 서비스가 기본 생성하는 시각과 웹 API가 새로 쓰는 검토 시각도 명시적 UTC를 사용합니다.

분기·반복 주차·교육 추천·오탐 집계와 수동 병합 후 후보 수 갱신은 한국 달력 기준입니다. 한국 4월 1일 오전 1시 사건은 UTC 날짜가 3월 31일이어도 Q2에 포함합니다. 집계 경계는 시작 포함·다음 분기 시작 제외이며, 마이크로초를 SQL에서 반올림하여 다음 날짜로 넘어가지 않도록 처리합니다. 이 프로젝트의 현대 한국 시각은 UTC+09:00입니다.

DB 스키마 변경이나 과거 원본 시각의 일괄 변환은 하지 않습니다. 문자열 컬럼에 새 기록의 UTC 오프셋을 유지하고 조회·집계에서 변환합니다. 저장된 과거 통계·추천은 자동 재작성하지 않으므로 배포 후 필요한 분기를 기존 생성 API로 재집계해야 합니다. 검토 후 보관 자료·교육 게시물과 충돌할 수 있으므로 운영 자료를 확인하고 명시적으로 실행합니다.

## 이벤트 응답 필드

- `timestamp_start`, `timestamp_end`: 시간대가 확인된 값은 `+09:00`이 포함된 ISO 8601입니다.
- `timestamp_timezone`: 확인된 새 시각은 `Asia/Seoul`, 시간대 없는 과거 기록은 null입니다.
- `event_date_local`: 확인된 발생 시각의 한국 날짜 `YYYY-MM-DD`입니다. 과거 시간대가 불명확하면 null입니다.
- `reporting_timezone`: `Asia/Seoul`입니다.

과거 시간대 없는 원문은 응답과 DB에서 보존합니다. UTC나 KST라고 추정해서 Z를 붙이지 않습니다. 과거 기록의 집계·필터는 기존 기록의 달력 날짜를 유지하며, 해당 결과가 확정된 시간대 변환인 것처럼 설명하지 않습니다. 이전 처리 API로 생성된 UTC-naive 사건도 과거 원문으로 남지만, 같은 event_id를 재전송하는 경우 기존 UTC 저장 계약에 맞춰 순간을 비교하여 불필요한 409를 피합니다. 이 비교는 기존 행을 수정하지 않습니다.

## 날짜 필터 API

관리자 `GET /api/events?date_from=2030-04-01&date_to=2030-04-01`은 한국 4월 1일 전체를 포함합니다. 두 날짜는 모두 포함이며, 하루 마지막 마이크로초도 빠지지 않습니다. 한쪽만 지정할 수 있습니다. 잘못된 날짜는 422, 시작이 종료보다 늦으면 400입니다. 날짜 필터 없는 기존 호출도 유지합니다.

시간대 불명 과거 기록은 기록된 날짜 기준으로 필터합니다. 목록 최상위 `legacy_time_policy: as_recorded`가 이 정책을 나타냅니다. 날짜 없는 과거 이벤트는 날짜 필터를 지정한 경우 제외합니다.

## 프론트 담당 적용 사항

1. 일반 시각 표시는 `Intl.DateTimeFormat` 또는 `toLocaleString`에 `timeZone: 'Asia/Seoul'`을 명시해야 합니다. `ko-KR`은 언어·형식만 정하며 브라우저 시간대를 한국으로 고정하지 않습니다.
2. 날짜 필터는 위 서버 파라미터를 권장합니다. 로컬 필터가 필요하면 `event_date_local`을 사용하고, ISO 원문을 날짜 문자열과 직접 비교하지 않습니다.
3. `timestamp_timezone: null`은 시간대 확인이 안 된 과거 기록입니다. 화면에서 임의 UTC·한국 시간으로 단정하지 않는 표시가 필요합니다.
4. 새 이벤트 정렬은 시간대 포함 시각을 파싱하여 비교합니다. 과거 불명 시각과의 절대시간 순서는 확정할 수 없습니다.

화면 코드는 이 변경에서 수정하지 않았습니다. 화면의 표시·필터 적용은 프론트 담당 후속 작업입니다.

## 검증

임시 SQLite DB와 CI의 PostgreSQL에서 UTC 저장·KST 응답, 같은 순간의 서로 다른 오프셋 재시도, 과거 원문 보존, 한국 자정·분기·주차 경계, 교육·오탐·수동 병합 집계, 날짜 필터 마지막 마이크로초를 검증합니다. 실제 서버·개발 DB·GPU·외부 API는 사용하지 않습니다.
