# 추론 프레임 버퍼와 만료 청크 처리

## 메모리 경계

서버 추론 실행기는 MP4 전체를 원본 프레임 목록으로 만들지 않고 한 프레임씩 디코딩·처리합니다. 클립 조립용 `ClipBuffer`는 30초 보관과 카메라별 원본 배열 바이트 상한을 동시에 적용합니다. 기본 상한은 256MiB이며, 새 프레임을 복사하기 전에 오래된 프레임을 제거합니다. 영상 해상도를 자동으로 줄이지는 않습니다.

```powershell
python -m inference_worker.run_server --camera-id CAM_001 --max-chunks 30 --buffer-mib 256
```

`--buffer-mib`는 최소 8입니다. `--max-chunks`의 유한 점검 모드는 유지하며 만료로 건너뛴 청크도 최대 시도 수에 포함합니다. 요약에는 실제 처리 수와 만료 수를 나눠 표시합니다. 기존 이벤트 전송은 별도 `--submit-events` 옵션과 PPE 검증 조건을 따릅니다.

256MiB는 보관하는 NumPy 원본 프레임 배열의 합계에 대한 상한입니다. 모델·GPU 메모리·OpenCV 내부 메모리·현재 디코딩 프레임·압축 청크·인코더·Python 객체와 전체 프로세스 RSS를 제한하는 값은 아닙니다. 여러 카메라는 각 프로세스의 버퍼 예산을 합산해야 합니다. 수동 호출하는 `ClipBuffer.select()`의 반환 복사본도 별도 메모리이며, 서버 실행기는 클립 선택 시 참조를 사용하고 인코딩 후 즉시 해제합니다.

기본 송출 설정인 640×480·15fps에서 7초 원본 배열은 약 92MiB입니다. 반면 1920×1080·30fps의 7초는 약 1.22GiB이므로 256MiB로는 전후 클립을 보장할 수 없습니다. 고해상도 시연 시 입력 fps·해상도 또는 명시적 버퍼 예산을 조정하고 실측해야 합니다. 메모리 상한에 도달하면 `[BUFFER LIMIT]`에 제거 수와 보관 바이트가 표시됩니다. 필요한 구간이 없어지면 `[CLIP INCOMPLETE]`로 기록하고 불완전한 클립을 정상 자료로 제출하지 않습니다.

## 시간축·오류 처리

- 디코더는 MP4 fps·프레임 수·해상도 상한과 선언된 구간 길이를 확인합니다. 캡처 시각 복원에는 프레임 수와 선언된 구간 길이를 사용하여 다음 청크와 겹치는 시각이 생기지 않게 합니다.
- 다운로드 404는 목록 조회 후 자료가 만료·정리된 경우로 처리합니다. 해당 청크를 다시 요청하지 않고 추적·위반 지속시간·클립 버퍼·대기 클립을 초기화한 뒤 다음 청크로 진행합니다. 누락 구간을 사이에 둔 프레임을 하나의 완전한 사건 클립으로 연결하지 않습니다.
- 403 등 권한 오류와 다른 HTTP 오류를 404로 취급하지 않습니다. 손상된 영상이나 모델 오류를 정상 처리로 숨기지 않습니다.
- 정상 디코딩 종료뿐 아니라 추론 예외 시에도 디코더를 닫고 임시 MP4를 제거합니다. 운영체제 강제 종료·전원 차단 시 정리까지 보장하는 기능은 아닙니다.

## 검증 범위

격리 테스트는 바이트 상한·오래된 프레임 제거·복사 독립성·시간 역전 거부, 합성 MP4의 순차 디코딩·시간축·명시적 종료·실패 정리, 404 이후 후속 청크 처리와 누락 클립 차단, 403 차단, 추론 예외 시 디코더 종료를 확인합니다. 실제 GPU 추론 성능·다중 카메라 RSS·처리 지연은 별도 실환경 검증 대상입니다. 이 변경은 카메라별 GPU 우선순위 신호 충돌을 해결하는 변경은 아닙니다.
