# 혼자 진행하는 안전모·조끼 관측 실증 안내

## 현재 상태
이 도구는 **수집·진단용 후보**다. 서버에 배포하지 않았고 실제 카메라/GPU로
검증하지 않았다. 자동 판정은 계속 꺼져 있다. 운영 서버를 끄거나 모델을
바꾸지 않는다. 카메라 PC에서 녹화한 로컬 영상은 이 도구가 있는 별도 테스트
작업 폴더에서 분석한다. 아래 명령은 그 후보 코드가 있는 폴더를 기준으로 한다.

## 준비
1. 기계가 가동되지 않고 보호구가 실제로 필요하지 않은 안전한 장소에서 한다.
2. 카메라 위치·밝기·모델 파일을 고정한다. 영상은 일정 FPS 방식으로 녹화한다.
3. 다른 사람이 나오지 않도록 한다. 타인의 개인정보가 있는 영상은 사용하지 않는다.
4. 상황마다 별도 영상으로 저장하고, 결과를 보기 전에 착용 상태를 기록한다.
5. 한 회는 사람이 충분히 보이는 상태로 3초 이상 관찰되도록 한다. 몇 초짜리
   조각 여러 개를 서로 다른 실험으로 세지 않는다. 정상과 애매한 영상도 보존한다.
6. Python의 기존 추론 의존성(OpenCV/Ultralytics 등)과 모델이 있는 **테스트 환경**을
   사용한다. 이 안내대로 실행한다고 의존성이 자동 설치되지는 않는다.

## 12회 기록표
각 행 결과에는 `사람/장비 탐지`, `unknown·추적끊김`, `영상 이상`, `추가 메모`를 적는다.
정답 열은 실제 녹화 영상을 보고 최종 확인한다. 이벤트가 생성되지 않은 정상
상황도 별도 성공/실패 장부에 남기고 가짜 사건 ID를 만들지 않는다.

손에 들고 있는 보호구가 착용으로 잘못 연결되는지도 별도로 확인한다.

## 실행 예 (한 줄로 입력)
후보 저장소 루트에서 실행한다. 경로는 본인이 준비한 파일 경로로 바꾼다.
`python`은 기존 추론 의존성이 설치된 Python 실행기여야 한다.

```powershell
python -m inference_worker.collect_scenario --video "D:\PPE-demo\solo05.mp4" --model "D:\PPE-test\best.pt" --output "D:\PPE-demo\solo05-observations.jsonl" --scenario-id solo05 --camera-id demo01 --helmet-label worn --vest-label not_worn --assume-constant-fps
```

이 명령은 영상을 새로 녹화하지 않는다. 기존 영상·모델 파일을 읽으며, 원본은
바꾸지 않는다. 새 JSONL만 기록한다. 사람이 없는 프레임과 정상/unknown도 남긴다.
파일이 이미 있으면 덮어쓰지 않으므로 새 이름을 사용한다.

기본 제한은 3,600프레임·120초다. 초과하면 미완료로 처리한다. 길이를 잘라
의심 부분만 선택하지 말고, 전체 시나리오를 제한 내에서 별도로 녹화한다.
시간은 프레임 번호/FPS 기준이므로 가변 FPS 영상·시간 누락은 별도 확인이 필요하다.

## 진단 요약
0.1초는 아래 예시의 **관측 간격 허용치**일 뿐 위반 판정 임계값이 아니다.
예를 들어 30 FPS 일정 영상은 프레임 간격 약 0.033초다. 실제 FPS를 확인하고
허용 관측 간격을 명시한다. 간격을 크게 늘려 누락을 정상으로 꾸미지 않는다.

```powershell
python -m inference_worker.summarize_scenario --input "D:\PPE-demo\solo05-observations.jsonl" --output "D:\PPE-demo\solo05-diagnostics.json" --max-sample-gap-seconds 0.1
```

완료 footer가 없거나 프레임 수·순서가 맞지 않으면 요약하지 않는다. 한 track이
일부 프레임에 없으면 그 시간을 unknown으로 넣는다. 나갔다 온 사람을 같은
사람이라고 임의 합치지 않는다. 어떤 frame에서도 사람이 없으면 진단 목록은
비어 있고, 이를 정상 착용으로 자동 채점하지 않는다.

## 결과 해석
- `decision_metric`은 보이는 것으로 추정된 프레임에서 장비 상자가 없던 비중이다.
  확률·검증된 신뢰도·자동 위반 판정이 아니다.
- unknown/시간누락/짧은 시나리오 등이 있으면 그 값은 null일 수 있다. 제외 이유와
  횟수를 함께 기록하며, 값이 나온 쉬운 사례만 정확도로 발표하지 않는다.
- 정상 착용인데 미착용 의심이 나오면 프레임의 탐지·연결 실패를 먼저 확인한다.
  시연을 통과시키려고 임계값만 낮추거나 라벨을 바꾸지 않는다.
- 이 12회는 시연의 주요 실패 상황을 확인하는 최소 계획이지 현장 정확도 증명이 아니다.
- 관리자 시험기록과 실제 자동확정은 다르다. 도구 결과만으로 자동확정을 켜지 않는다.

## 보관과 연결 범위
출력에는 얼굴/영상/좌표가 없지만 시간·동작 상태가 있으므로 테스트 자료로만
취급한다. 시나리오 ID에 이름을 쓰지 않는다. 운영 DB·교육추천·통계에는 기록하지
않는다. 자동 삭제는 설치하지 않았으며 테스트가 끝나면 사용자가 보관 여부를 정한다.
실제 사용자 검토 없는 시나리오 라벨을 개별 track의 정답으로 자동 전환하지 않는다.

요약기는 프레임×추적ID×2(PPE)의 합성 관측 수를 200만 개로 제한한다.
초과하면 조용히 일부만 계산하지 않고 실패한다. 이때는 좋은 프레임만 골라
줄이지 말고 추적 ID가 과도하게 바뀐 원인이나 시나리오 길이를 먼저 확인한다.
