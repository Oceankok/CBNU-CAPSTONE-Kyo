# 미착용 모델 출력과 이벤트 연결

## 판정 근거

`person`, `helmet`, `no_helmet` 클래스를 가진 로컬 YOLO 모델의 **실제 no_helmet 탐지 점수**를 기존 이벤트 API에 연결합니다. 사람 탐지 점수나 안전모 박스가 없다는 사실을 위반 점수로 바꾸지 않습니다. `verified_ppe_confidence`의 verified는 전용 미착용 클래스 출력이 확인되었다는 뜻이며 정답 판정·보정된 확률·관리자 검토 완료를 뜻하지 않습니다.

- 기존 머리 영역 기준(사람 박스 상단 30%)에 들어오는 no_helmet 탐지만 연결합니다. 같은 탐지가 여러 사람의 머리 영역에 들어오면 점수를 연결하지 않습니다.
- 같은 머리에 helmet과 no_helmet이 함께 있으면 unknown으로 두고 관측을 다시 시작합니다.
- 기존 탐지 임계값인 0.5 이상의 유한 점수를 사용합니다. bool·NaN·무한대·범위 밖 점수는 거부합니다.
- 유효한 미착용 관측이 3초 이상 이어져야 합니다. 이전의 단순 미탐지 시간은 합산하지 않으며, 관측 간격이 0.5초를 넘거나 미착용 탐지가 끊기면 구간을 다시 시작합니다.
- 해당 구간의 no_helmet 점수 중 최솟값을 기존 `confidence`로, 실제 관측 프레임 수를 `frame_sample_count`로 보냅니다. 관리자 검토 전 후보 이벤트라는 기존 의미는 유지합니다.
- 검증 후보를 이미 만든 뒤 짧게 미착용 탐지만 사라진 경우 같은 사람의 연속 관측에서 다시 후보를 만들지 않습니다. 사람이 사라지거나 착용·충돌 등으로 상태가 재설정되면 새 관측이 필요합니다. 영구 사건 중복 제거·카메라 간 동일인 식별은 아닙니다.

기존 사람 IoU tracker와 서버 DB/API 형식은 변경하지 않습니다. 안전조끼 자동 이벤트 생성·모델 재학습·ROI는 추가하지 않습니다. 구역에서 안전모가 필수가 아니거나 정책이 완성되지 않으면 전송하지 않습니다.

## 모델 선택 및 실행

기존 3클래스 기본 모델은 진단용 기본값으로 유지합니다. 이 모델에 `--submit-events`를 사용하면 API 연결 전에 명확한 오류로 중단합니다. 이벤트를 생성하려면 팀에서 검증한 4클래스 이상 모델을 명시합니다. 로컬 파일이 없으면 오류를 반환하고 모델을 다운로드하지 않습니다.

```powershell
# 기존 방식대로 서버 주소·처리 node 토큰을 안전하게 환경에 설정한 상태입니다.
python -m inference_worker.run_server `
  --camera-id CAM_001 `
  --model-path 'runs/ppe/final_ppe_baseline-2/weights/best.pt' `
  --submit-events `
  --max-chunks 30
```

위 파일은 저장소에 존재하는 4클래스 모델의 경로 예시이며 시연용 최종 모델로 확정한 것은 아닙니다. 확인한 SHA-256은 `2347ad2bbaf21d56c5590d44edcfe69395ad8c650a4223b70d34978f057d7143`입니다. 실제 전달받은 파일·클래스 목록·미착용 양성 사례를 AI 담당자와 확인한 뒤 경로를 교체해야 합니다. 클래스 이름이 다르면 임의로 대응시키지 않습니다.

모델 파일의 SHA-256 앞 16자리로 `ppe-<hash>` 버전을 기록합니다. 경로를 바꿔도 같은 파일이면 같은 버전이며 실제 이벤트에 이 값이 저장됩니다.

시작 직후에는 먼저 기존 2초 전 영상 구간을 확보한 뒤 미착용 관측을 시작하고, 3초 관측 후 2초 후 영상을 기다립니다. 첫 완전한 사건 클립은 정상적인 연속 입력에서 시작 후 약 7초 이후에 준비될 수 있습니다. 추론·인코딩·네트워크 소요 시간은 별도이며 기존 전송·비식별화 경로를 사용합니다. 버퍼가 작거나 영상이 끊기면 불완전한 클립을 제출하지 않습니다.

## 검증 및 적용 범위

격리 테스트는 실제 평가·사람 tracker·위반 tracker·runner를 연결하고 모델 탐지 결과만 fixture로 제공합니다. 별도의 QualifiedCandidates 패치 없이 3초 관측 → 점수·프레임 수·모델 버전 → 완전한 전후 클립 → 전송 호출을 확인합니다. 애매한 매칭·상충 라벨·끊긴 관측·중복·정책 차단·3클래스 시작 오류도 확인합니다.

로컬 CUDA에서 모델 로드·추론과 기존 이미지·이전에 제공한 영상 앞 12초(4fps)를 확인했으나, 해당 자료에서는 유효한 no_helmet 탐지를 확보하지 못했습니다. 일부 error_cases 이미지는 박스가 그려진 분석 결과이므로 정확도 평가 자료로 취급하지 않습니다. 실모델의 미착용 양성 이벤트 생성·현장 정확도·실 카메라 종단간 PASS는 별도 원본 영상으로 검증해야 합니다. 임계값을 낮추거나 임의 점수를 넣어 이를 통과시키지 않습니다.

이 변경의 테스트에서 운영 DB·방송·외부 API를 사용하지 않습니다. 실제 서버 적용은 검토·병합 후 같은 버전의 호스트 소스와 서버 이미지를 맞추어 진행하며 DB 스키마는 v16 그대로입니다.
