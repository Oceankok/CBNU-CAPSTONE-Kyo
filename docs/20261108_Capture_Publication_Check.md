# 촬영 완료 파일 공개 검증

노트북 두 채널 로그에서 `moov atom not found` 후 같은 조각이 HTTP 202로 접수되는 현상을 확인했습니다. 원인은 송신 시점에 MP4가 미완성이라는 점까지 확인했으며, 특정 서버 변경이 원인이라는 주장은 확인되지 않았습니다. 서버 추론을 중지해도 발생했다는 사용자 확인을 받았습니다.

촬영기는 `.mp4.part`에 기록하고 FFmpeg의 완료 목록에 올라온 조각을 같은 폴더의 `.mp4`로 전환합니다. FFmpeg가 파일을 닫는 중인 Windows 공유 위반은 다음 촬영 반복에서 다시 시도합니다. 기존 송신기의 마지막 파일 제외와 429 재시도는 유지합니다. `.part` 잔여 파일도 재시작 번호 계산에 포함합니다.

검증 결과는 다음과 같습니다.

- PostgreSQL 17 격리 DB에서 촬영·송신·영상 접수 테스트 23개 통과, 테스트 컨테이너 제거 완료입니다.
- 실제 FFmpeg/ffprobe 9.0.2와 인물 없는 합성 영상 두 채널을 약 10초씩 실행했습니다. 송신 가능 파일 총 16개를 읽었고 ffprobe 오류 0건, 인코더 종료 코드 모두 0입니다. HTTP는 실제 전송하지 않고 성공 후 삭제 동작으로 대체했습니다.
- 미완성 파일 비공개, 완료 목록의 불완전 줄·경로 차단, 기존 파일 보존, 공유 위반 후 재시도, 재시작 번호와 명시적 영상 스트림 선택을 확인했습니다.

수정 전 합성 환경에서는 원래 오류가 재현되지 않았으므로, 노트북 두 실제 카메라에서의 최종 재확인이 필요합니다. HTTP 422의 상세 사유는 이번 첨부 로그에 없어 확정하지 않았으며 이번 변경은 해당 상태 코드의 재연결 정책을 변경하지 않습니다. 실제 서버·DB·카메라·GPU·방송은 변경하지 않았습니다.
