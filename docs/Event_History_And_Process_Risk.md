# 발생 구역 보존·오탐 재검토 집계·공정 가중치

## 발생 시점 정보
새 이벤트를 접수하는 트랜잭션에서 카메라의 구역과 공정을 이벤트에 복사한다.
목록·상세·필터·요약·분기 통계·교육 추천은 이 값을 사용한다.
카메라를 이동하거나 공정을 변경해도 이전 이벤트는 바뀌지 않는다.

스키마 21로 갱신할 때 기존 이벤트는 현재 카메라 정보를 한 번 복사한다.
`context_source=upgrade_current`는 발생 당시 정보가 복원된 것이 아니라 갱신 당시 값을 고정했다는 뜻이다.
새 이벤트는 `capture`로 기록한다. 이미 과거에 바뀐 구역은 추정해 복원하지 않는다.

## 오탐 집계
오탐 → 오탐은 건수를 추가하지 않고, 오탐 → 확정/보류는 기존 기여분을 차감한다.
다른 판정 → 오탐은 한 번 추가한다. 검토 이력은 계속 보존한다.
분기 통계 생성도 검토 쓰기와 같은 잠금으로 일관된 결과를 읽는다.

기존 중복은 스키마 갱신 시 현재 검토와 검토 이력에 남은 오탐 기여분으로 보정한다.
기존 집계에서 식별 가능한 기여분을 제외한 잔여 건수는 `legacy_false_positive_summary`에 분기별로 남긴다.
따라서 이미 물리적으로 삭제된 과거 이벤트의 익명 집계는 잃지 않는다.
원본 검토 기록까지 없어진 중복이나 외부에서 직접 수정한 집계는 정확하게 판별할 수 없다.

## 시연용 공정 위험도
기존 우선순위 공식의 계수는 유지한다.
기본값은 1.0, 공정 이름이 `프레스`, `절단`, `press`, `cutting`이면 1.5로 한다.
이는 교육 우선순위를 위한 초기 운영값이며 산업안전 위험성 평가를 대체하지 않는다.
같은 구역/PPE에 여러 공정이 있으면 확정 이벤트 수로 가중 평균한다.
PPE 통계·구역 통계·교육 추천에 같은 기준을 적용한다.

서버 환경변수 `PPE_PROCESS_RISK_WEIGHTS`에 JSON 객체를 지정하면 공정별 값을 변경할 수 있다.
예: `{"프레스":1.5,"절단":1.5,"용접":1.2}`. 값은 0~5의 유한한 숫자만 허용한다.
공정 이름은 공백 제거·영문 소문자 변환 후 정확히 일치시킨다.
변경 후 서버 갱신과 분기 통계/교육 추천 재생성이 필요하다.
이 PR은 실제 서버에 값을 설정하거나 배포하지 않는다.
