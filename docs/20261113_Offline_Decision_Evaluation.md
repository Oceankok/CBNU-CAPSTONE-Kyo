# Offline event-score evaluation

This tool measures supplied scores against supplied human labels. It does not run
inference, modify a model, access a database, write review decisions, choose an
operational threshold, or enable automatic confirmation.

## Input

UTF-8 JSONL, exactly these five fields on each line:
- `event_id`: unique nonblank exact identifier. One score per event in one run.
- `model_version`: nonblank exact identifier of the scored model/version.
- `ppe_type`: supported PPE vocabulary (`helmet`, `vest`, `goggles`, `gloves`,
  `safety_shoes`, `hearing_protection`, `mask`, `harness`).
- `label`: human-provided `violation` or `non_violation`.
- `score`: finite JSON number in [0,1], not a boolean or string.

Blank lines, extra/missing fields, duplicate JSON keys, duplicate event IDs
(including across model/PPE groups), unknown labels, NaN and infinities fail the
whole run. Compare multiple models on the same events using separate runs; do not
rename duplicated events just to satisfy the check. Uncertain/unlabelled events
need adjudication or a separately documented exclusion, not a fabricated label.

**Synthetic format example only; not real labels or accuracy evidence:**

```json
{"event_id":"synthetic-event-1","model_version":"synthetic-model","ppe_type":"helmet","label":"violation","score":0.9}
{"event_id":"synthetic-event-2","model_version":"synthetic-model","ppe_type":"helmet","label":"non_violation","score":0.2}
```

## Run

From the repository root, using an explicitly chosen experimental threshold:

```sh
python -m backend.auto_decision.evaluate_dataset labelled_events.jsonl --threshold 0.9
```

The example threshold is not an approved default. Successful output is a JSON
report on stdout; invalid input exits 2 without a partial report. To save a report,
redirect stdout to a separate file, never the input dataset. Source rows are not
included in output. No dataset or threshold is generated by this tool.

## Interpretation

`score >= threshold` predicts violation. Reports contain overall and separate
model/PPE confusion counts (`tp`, `fp`, `tn`, `fn`), sample count, human-positive and
human-negative counts, predicted-positive count, precision and recall.

- Precision = TP / (TP + FP).
- Recall = TP / (TP + FN).
- Zero denominators produce JSON `null`, not 0, 1 or NaN.

The overall totals must not hide a poorly sampled or failing model/PPE group.
These are sample estimates, not calibrated probabilities or acceptance evidence.
Before activation, separately define representative held-out event-level labels,
minimum samples per model/PPE, treatment of occlusion/unknown/missing evidence,
acceptance thresholds and human review rules. Scores must correspond to the
whole-event evaluator being validated, not be silently substituted with a
single-frame score. Split train/tuning/evaluation data by source episode to avoid
leakage, and do not treat 3-second fragments from one event as independent labels.
No minimum sample size or pass/fail acceptance policy is invented here.

If the dataset labels only events already generated by the system, undetected
incidents are absent. Its recall is conditional on those supplied events, **not
end-to-end detection recall**. Measuring full-system recall requires independently
annotated source episodes (including missed incidents) and a separate matching /
scoring protocol. The evaluator does not reconstruct omitted incidents or assign
missing scores. Never present this report as whole-system accuracy or activation
approval.
