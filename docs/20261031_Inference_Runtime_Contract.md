# 다중 추론 우선순위와 호스트 실행 버전 확인

## 실행 세션별 우선순위

`PUT /api/processing/inference-load`에 선택 필드 `session_id`를 추가했습니다. 새 추론 실행기는 실행마다 UUID hex를 만들고 갱신·해제에 같은 값을 사용합니다. 한 node에서 카메라 A·B를 별도 실행해도 A의 해제가 B의 신호를 지우지 않습니다. 서버는 인증된 node와 session_id의 쌍으로 저장하며, 응답에도 session_id를 돌려줍니다. 새 클라이언트는 응답에서 이를 확인하여 구버전 서버가 필드를 조용히 무시하는 상태를 감지합니다.

```json
{"busy":true,"ttl_seconds":30,"session_id":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"}
```

session_id 없는 기존 호출은 기존 node 신호로 유지합니다. 기존 해제는 새 세션 신호를 지우지 않습니다. 다만 구버전 추론 프로그램끼리는 실행 구분이 없으므로 다중 카메라 시연에는 새 프로그램으로 맞춰야 합니다.

비식별화 worker와 호스트 AI 작업 접수·GPU 양보 확인은 유효한 기존 신호와 새 세션의 최댓값을 함께 봅니다. 중단된 세션은 TTL 후 영향을 잃으며 다음 신호 갱신에서 만료 행을 정리합니다. node별 동시 세션은 32개로 제한하고 기존 세션 갱신·해제는 허용합니다. 비활성 node·처리 권한이 해제된 node의 신호는 집계하지 않습니다.

이 신호는 협력적인 우선순위 힌트이며 GPU 상호 배제 잠금이 아닙니다. 추론끼리 GPU 실행을 순차화하지 않습니다. 기존 10초 갱신·최대 30초 TTL을 사용하므로 단일 추론이 TTL보다 오래 걸리는 상황은 실측해야 합니다.

## 스키마 v16 적용

`processing_inference_session` 테이블을 추가합니다. 기존 신호·사용자·이벤트·미디어를 재작성하지 않습니다. PostgreSQL과 테스트용 SQLite에서 v15→v16을 지원합니다.

실제 배포 전 새 API 이미지의 기존 명시적 db-init 절차로 v16 이관을 수행하고 API·DB 버전을 맞춰야 합니다. 기존 Release.ps1은 운영 DB를 자동 이관하지 않으며, 새 API의 readiness는 v16을 요구합니다. 운영 적용은 기존 백업·정지·이관·새 API 기동 절차에서 진행합니다. 이 PR 작업에서는 실제 서버 DB·서비스·예약 작업을 변경하지 않았습니다.

## 읽기 전용 버전 확인

서버 PC의 프로젝트 루트에서 기존 처리 node 토큰과 서버 주소를 환경에 설정한 상태로 실행합니다. 토큰·비밀번호를 명령 인자나 문서에 적지 않습니다.

```powershell
python -m backend.runtime_version
```

프로그램은 로컬 Git 커밋과 미커밋·미추적 변경 여부를 읽고, 처리 node 전용 `GET /api/processing/runtime-version`과 비교합니다. 서버 응답은 API 이미지 빌드 시 기록한 커밋, 요구·실제 DB 버전, 처리 모드를 포함합니다. Release 워크플로는 검증된 커밋을 이미지 빌드 인자로 전달합니다. 별도 로컬 빌드에서 커밋을 넣지 않았으면 서버 버전은 null이며 일치한다고 가정하지 않습니다.

| status | 의미 |
| --- | --- |
| matched | 호스트 커밋·API 이미지 커밋이 같고 호스트 변경이 없으며 DB 버전이 일치합니다. 종료 코드 0입니다. |
| different | 커밋이 다릅니다. |
| dirty | 호스트 체크아웃에 변경이 있습니다. |
| unknown | Git 또는 이미지 커밋을 확인할 수 없습니다. |
| schema_mismatch | 실제 DB 버전과 API가 요구하는 버전이 다릅니다. |
| server_version_unavailable | 서버 접속·인증·메타데이터 조회에 실패했습니다. |

matched 외에는 종료 코드 2입니다. 소스 갱신·checkout·설치·재시작은 수행하지 않습니다. URL·인증 토큰·Git 상태의 파일명·설정 파일 내용을 출력하지 않습니다.

비식별화 worker와 추론 프로그램은 시작 시점의 커밋·변경 여부도 로그에 남깁니다. 명령은 현재 디스크의 체크아웃을 비교하므로 이미 실행 중인 Python 프로세스가 읽은 모듈을 증명하지는 않습니다. 코드 갱신은 호스트 프로그램을 정지한 상태에서 진행하고, 다시 시작한 로그와 배포 커밋을 대조해야 합니다. 기존 창 없는 실행·자동 시작 설정은 그대로이며 GPU 프로그램은 수동 실행입니다.

## 검증

격리 DB에서 카메라 A 해제 후 B 신호 유지, 기존 해제와 새 세션 격리, node 간 소유권, TTL·비활성·세션 상한, 미디어·호스트 AI 작업 양보, v15 이관 반복 실행과 계정·기존 신호 보존을 확인합니다. 버전 검사 테스트는 가짜 Git/HTTP 응답을 사용하며 CI의 Docker 통합에서는 실제 빌드 인자가 API에서 조회되는지도 검증합니다. 실제 GPU·방송·외부 AI는 사용하지 않습니다.
