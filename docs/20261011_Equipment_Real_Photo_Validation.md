# 장비 후보 인식 백엔드: 실물 사진 검증 결과

2026-10-11 실제 ChatGPT 구독 연결과 SCRFD CUDA 비식별화를 사용하여 공개 실물 장비 사진 2장을 검증했습니다. 두 제공 방식 모두 `gpt-6.1-sol`을 지정했습니다. 총 4개 조합이 통과했습니다.

| 방식 | 사진 | 주요 후보 | 분석 API 응답 시간 | 결과 |
|---|---|---|---:|---|
| `codex_chatgpt` | 지게차 | 지게차 / 카운터밸런스 지게차 | 14.02초 | PASS |
| `codex_chatgpt` | 드릴링 머신 | 수직 기둥형 드릴링 머신 / 드릴 프레스 | 10.06초 | PASS |
| `chatgpt_oauth` | 지게차 | 노란색 카운터밸런스 지게차 | 14.47초 | PASS |
| `chatgpt_oauth` | 드릴링 머신 | 기어식 직립 드릴링 머신 | 9.22초 | PASS |

시간은 업로드 API 요청부터 분석 응답까지이며 비식별화·모델 초기화/캐시·네트워크·외부 분석 시간을 포함합니다. 단일 실행 결과이므로 제공 방식의 성능 우열이나 평균 처리 시간으로 사용하지 않습니다.

## 통과한 흐름

1. 관리자 인증 후 실제 JPEG를 장비 후보 분석 API에 업로드했습니다.
2. 실제 SCRFD CUDA 비식별화 완료 결과만 외부 제공업체로 전달했습니다.
3. 모든 조합에서 분석 상태 `analyzed`, 오류 코드 `null`과 적절한 주요 장비 후보를 확인했습니다. 임의의 확률값 대신 `confidence=null`로 반환했습니다.
4. 후보 분석만으로 장비가 자동 등록되지 않는 것을 확인했습니다.
5. 관리자에게 제공한 근거 이미지를 JPEG로 디코딩할 수 있는 것을 확인했습니다. 미인증 접근은 401, 작업자 접근은 403이었습니다.
6. 후보 중 대상 장비를 선택하고 관리자가 이름을 변경한 값으로 등록했습니다. 등록 이름과 선택한 PPE는 관리자 입력값으로 저장했습니다.
7. 같은 후보를 두 번 확정하는 요청은 409로 거절했습니다.
8. 장비 목록에 정확히 한 건이 추가된 것을 확인했습니다.
9. 장비를 카메라에 연결하고 적용 PPE 미리보기에 관리자 지정 PPE가 포함되는 것을 확인했습니다. 이 검증은 PPE 조회이며 실제 탐지·경고 방송에 규칙을 적용한 테스트가 아닙니다.

HTTP API는 로컬 TestClient로 호출했습니다. 개발 DB 대신 임시 DB를 사용했고 근거 파일도 임시 폴더에 저장하여 실행 종료 후 제거했습니다. 운영 웹 화면 조작은 수행하지 않았으며 프론트 화면을 수정하지 않았습니다. 이전 수정 이후 백엔드 전체 자동 회귀 테스트 62개가 통과한 상태이고, 이번 실물 검증에서 제품 코드는 추가 변경하지 않았습니다.

## 관찰 및 판정 범위

사진 배경의 장비나 부속 장치도 후보로 반환됐습니다. 두 방식은 가려진 배경 장비의 종류를 다르게 추정하기도 했습니다. 주요 지게차와 드릴링 머신 후보는 적절했으며, 불확실한 후보에는 보이는 근거와 확인이 필요한 내용을 설명했습니다. 관리자 선택·수정·확정 절차를 유지합니다.

이번 결과는 **장비 후보 인식 백엔드의 연결·등록·연동 기능 검증 PASS**로 정리합니다. 두 장의 사진으로 모든 장비의 인식 정확도나 현장별 시연 안정성을 보장하지 않습니다. 사진에 사람이 없으므로 얼굴 모자이크 품질을 평가한 검증도 아닙니다. 장비 후보 확인 화면의 프론트 연동, 실제 현장 사진·카메라 프레임의 대표 사례, 장기 토큰 갱신·실제 구독 한도 도달은 별도 검증 대상입니다.
