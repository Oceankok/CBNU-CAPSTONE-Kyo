# 3클래스 모델로 안전모·조끼 미착용 의심 판정

## 모델

기본 가중치는 저장소 루트 `best.pt`입니다. 2026-09-30 업로드 커밋
`490d1fb`의 체크포인트이며, 저장된 클래스는 `0: helmet, 1: vest, 2: person`,
체크포인트 날짜는 `2026-09-30T14:31:19.283570`입니다.
가중치는 수정하거나 재학습하지 않았습니다. 다른 가중치는 `--model-path`로 지정합니다.

## 웹캠 실행 (프로젝트 루트, Windows)

```powershell
python src/realtime_helmet_monitor.py
```

카메라 선택은 `--camera 1`을 사용합니다. `q` 또는 ESC로 종료합니다.
사람과 보호구 박스, 사람별 helmet/vest 상태를 표시합니다. 3초 연속 미탐지면
빨간색 사람 박스와 `[SUSPECTED]` 로그를 출력합니다.

기존 로컬 백엔드 DB·카메라 등록·미디어 처리 환경에서 검수 이벤트도 저장하려면:

```powershell
python src/realtime_helmet_monitor.py --camera-id CAM_001 --submit-review-candidates
```

기본 실행은 화면/로그만 출력합니다. 이벤트 저장 옵션은 서버 방송 설정에 따라
예방 방송을 생성할 수 있습니다. 웹캠 저장은 동기식이며 미디어 처리 동안 관측이
중단되므로 다음 관측의 시간 간격 검사로 연속 판정이 초기화됩니다.
웹캠 클립은 최근 최대 5초를 저장하며 서버 청크 방식의 전후 2초 보장은 하지 않습니다.

## 서버 영상 연동

기존 처리 노드 인증/서버 주소 설정을 유지하고 실행합니다.

```powershell
python -m inference_worker.run_server --camera-id CAM_001 --model-path best.pt --submit-review-candidates --max-chunks 100000
```

서버에는 해당 카메라/구역의 필수 보호구를 `helmet`, `vest`로 설정해야 합니다.
조끼만 필수인 구역도 처리합니다. 작업영역 ROI는 사람 발밑 중심점으로 판정하는
기존 규칙을 유지합니다. 서버 청크 경로는 전후 영상과 정책 변경·스트림 단절
검사를 유지하며, 각 보호구 이벤트/클립을 별도로 생성합니다.
여러 카메라는 기존 `inference_worker.run_multi`에 같은 모델/검수 옵션을 전달합니다.

`--submit-events`는 실제 미착용 클래스 점수를 요구하는 기존 모델용 경로입니다.
이번 3클래스 모델은 `--submit-review-candidates`를 사용합니다.
이벤트는 `ppe_type=helmet/vest`, `review_only=true`, `confidence=null`, `pending`으로
저장하며 미착용 확정 여부는 검수에서 결정합니다.

## 판정과 한계

- 사람 박스 위쪽 30%에서 안전모 중심, 높이 15~70%에서 조끼 중심을 연결합니다.
  보호구 박스 면적의 80% 이상이 사람 박스 안에 있어야 합니다.
- 하나의 보호구가 여러 사람에게 연결되면 해당 종류의 판정은 보류합니다.
- 사람이 작거나(너비 12px 미만/높이 40px 미만), 화면 경계에 잘렸거나,
  다른 사람 박스가 판정 영역의 30% 이상을 가리면 미착용 의심을 보류합니다.
- 사람 ID와 보호구별로 3초 타이머를 분리합니다. 0.5초를 초과하는 관측 간격,
  사람 누락, 착용/판정불가 상태, 구역 정책 변화는 연속 관측을 끊습니다.
- 연속 의심 상태에서는 보호구별 한 번만 후보를 생성합니다.
- 수치들은 기하학적 초기 휴리스틱이며, 실측 성능으로 보정된 임계값은 아닙니다.
  실제 포즈·물체 가림을 완전히 알 수 없으며, 검출 누락도 미착용 의심을 만들 수 있습니다.
- 기존 탐지 mAP는 이 미착용 판정의 정확도를 뜻하지 않습니다. 현장 영상의
  미착용/착용/가림 구간으로 별도 precision/recall을 평가해야 합니다.

## 검증

단위 테스트는 사람별 연결, 동시 미착용, 착용 재확인, 화면 잘림, 겹침,
시간 단절과 보호구별 독립 타이머를 검사합니다. 오프라인 서버 통합 테스트는
조끼 전용/헬멧·조끼 동시 구역, 검수 이벤트 메타데이터와 클립 전달을 검사합니다.
실제 카메라와 GPU에서의 추론 속도·판정 정확도는 별도 검증이 필요합니다.
