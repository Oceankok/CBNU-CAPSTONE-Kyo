# 서비스 범위 문서 갱신을 위한 백엔드 구현 사실 (#144)

이 문서는 문서 담당자가 서비스 범위·개인정보 설명을 현재 코드와 대조할 수 있도록 정리한 기술 확인표입니다. 법적 검토나 정책 승인 문서가 아닙니다. 기준은 main `3615f6bef3055a9325402713a2a446c9be4d9dfb`입니다. 미병합 후속 PR은 아래에 별도로 구분합니다.

## 기존 원칙과의 기술적 대응

- 적용 범위: 구역의 PPE 안전 이벤트와 검토·교육 추천에 사용하며 개인 식별이나 구역 간 이동 추적을 구현하지 않습니다.
- 데이터 최소화: 연속 영상 상한, 재처리 원본 TTL, 원본 비공개, 삭제 결정 후 결과 게시 차단, 임시 파일 정리를 적용합니다.
- 집계 중심 제공: 교육 추천은 구역·PPE 기준이며 작업자에게 관리자 집계 근거를 노출하지 않습니다.
- 징계·평가 분리: 영상 속 개인과 로그인 계정을 자동 연결하거나 개인별 평가 점수를 산출하는 기능은 없습니다. 조직의 실제 이용 목적·운영 규정은 별도 정책으로 확인해야 합니다.

## 검증과 실제 운영 상태의 구분

- main에는 격리 SQLite/PostgreSQL 회귀 테스트와 실제 Docker API↔CUDA worker 검증 도구가 포함되어 있습니다. 실제 worker 검증 기록은 `docs/20261013_GPU_Worker_Real_Validation.md`를 참고합니다.
- 한국어/영어 실제 스피커 출력은 `docs/20261013_Broadcast_Real_Validation.md`에 기록되어 있습니다. 별도 현장 PC에서 영상 송신부터 추론·클립·방송까지 이어지는 전체 시연 검증과는 구분합니다.
- CI 성공·이미지 게시 성공·실제 승인 배포 완료는 각각 다른 상태입니다. PR #166 병합 후 이미지 게시는 성공했지만 해당 Release의 deploy job은 실행되지 않았습니다.
- 서버 PC는 자원 사용을 줄이기 위해 필요할 때 수동으로 시작·종료하는 방식으로 운영합니다. 항상 켜진 공개 서버로 설명하지 않습니다. 외부 HTTPS 주소·시연 네트워크는 #152·#154의 확정이 필요합니다.
