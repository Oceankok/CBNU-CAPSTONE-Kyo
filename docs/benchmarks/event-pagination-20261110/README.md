# 이벤트 페이지네이션 전후 측정

2026-11-10 실행 결과. 이 디렉터리의 `legacy.json`, `paged.json`에 각 표본과 환경을 보존했다.
기본 limit=50 적용은 **프론트 전환 완료 후 병합/배포**해야 한다.

## 조건

- 같은 Windows PC, Python 3.12.10, 전용 Docker PostgreSQL 17.11
- 이전 코드 `aea3502264085268f59ddd7eb650efbf0a4c8091`의 실제 전체 목록 API와
  제안 구현 `9fdf67eb53c41dd4fb55a14d00d4995ffcb4f0ec`의 실제 API를 별도 프로세스에서 실행
- 각각 임의의 격리 스키마를 생성하고 같은 합성 이벤트 1,000/10,000건을 넣음
- 검토 대기 60%, 검토 전용 10%, 이벤트 10건당 파일 없는 이미지 메타데이터 1건
- 엔드포인트마다 워밍업 1회 제외 후 3회 측정, 아래 시간은 중앙값
- HTTP는 FastAPI TestClient, DB 연결은 localhost. 인증·직렬화를 포함하되
  Cloudflare/TLS·브라우저 렌더링·실제 미디어 다운로드·GPU는 포함하지 않음
- 운영 DB와 실제 파일을 사용하지 않았으며 테스트 스키마·컨테이너는 실행 후 제거

## 결과

| 이벤트 수 | 조회 | 중앙 응답 시간 | 응답 바이트 | SQL 호출 수 | DB 연결 수 |
|---:|---|---:|---:|---:|---:|
| 1,000 | 이전 전체 목록 | 4.560초 | 1,085,083 | 3,108 | 102 |
| 1,000 | 기본 첫 50건 | 0.231초 | 56,973 | 17 | 10 |
| 1,000 | 요약·최근 대기 10건 | 0.062초 | 3,453 | 3 | 2 |
| 10,000 | 이전 전체 목록 | 43.274초 | 10,859,984 | 31,062 | 1,002 |
| 10,000 | 기본 첫 50건 | 0.286초 | 57,024 | 17 | 10 |
| 10,000 | 요약·최근 대기 10건 | 0.089초 | 3,460 | 3 | 2 |

SQL 호출 수는 어댑터의 execute 호출, 연결 수는 연결 객체 생성 횟수이다.
드라이버 초기 설정 등 모든 PostgreSQL 프로토콜 메시지를 세는 수치는 아니다.

20초마다 새 응답을 3번 받는다는 단순 계산에서, 10,000건 알림 조회의 본문량은
전체 목록 약 32.58MB/분에서 요약 약 10.38KB/분으로 줄어든다. 이것은 gzip·헤더·캐시와
실제 요청 겹침을 제외한 계산이다. 이전 요청은 20초보다 오래 걸렸으므로 실제 브라우저가
그 속도로 응답 3개를 받는다고 실측한 것이 아니다.

## 해석과 한계

첫 화면과 알림 갱신에서 전체 이벤트 수에 비례하는 응답 크기·부가 조회를 피할 수 있음을
보여 준다. 프론트가 목록 페이지와 summary API로 전환해야 효과가 실제 화면에 적용된다.

이전 전체 목록과 현재 페이지/요약은 의도적으로 반환하는 자료의 범위가 다르다.
변경 사이의 일괄 조회·개인정보 응답 필드 차이도 포함하므로 기본 limit 한 줄만의
인과 효과를 분리한 시험이 아니다. 시스템의 다른 부하는 고정하지 않았고 표본은 3회이므로
수치를 운영 SLA나 동시 사용자 부하 한계로 사용하면 안 된다.

인덱스가 모든 정렬 표현식을 최적화한다는 의미도 아니다. 시간대 변환 정렬과 집계는 여전히
전체 조건 집합을 읽을 수 있다. 목록의 processing job 조회는 포함된 미디어마다 남아 있어
DB 연결 수가 1로 줄지는 않는다. 이번 범위에서는 페이지 크기로 작업량을 제한한다.

offset 방식은 요청 사이 신규 생성·검토·병합이 발생하면 항목이 이동할 수 있다.
프론트는 데이터 변경 시 첫 페이지로 갱신해야 하며 동시 변경 상황의 중복/누락 없는
커서 페이지네이션을 구현한 결과로 해석하면 안 된다.

## 재실행

전용 테스트 PostgreSQL DB 이름은 `kyo_test`로 시작해야 한다. 운영 URL은 받지 않는다.
현재 checkout과 이전 checkout을 각각 준비한 후 같은 스크립트를 별도 프로세스로 실행한다.

```powershell
# PPE_TEST_POSTGRES_URL은 격리 테스트 DB의 연결 값으로 먼저 설정한다.
git worktree add --detach C:\Temp\kyo-pagination-before aea3502264085268f59ddd7eb650efbf0a4c8091
python deploy/tests/benchmark_event_pagination.py --checkout C:\Temp\kyo-pagination-before --variant legacy --output C:\Temp\legacy.json
python deploy/tests/benchmark_event_pagination.py --variant paged --output C:\Temp\paged.json
```

각 실행은 스키마를 자동 제거하지만 PostgreSQL 컨테이너 자체의 수명은 실행자가 관리한다.
기존 API 계약·정렬·필터 테스트와 기본 50건/다음 페이지 순회 테스트는
`backend.tests.test_event_pagination`에서 실행한다.
