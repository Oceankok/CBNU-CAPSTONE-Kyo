# 구역 기본 PPE와 장비별 추가 PPE

## 현재 #101/#104의 계약

`zone_rule.required_ppe`와 `/api/zones`의 `required_ppe`는 구역 전체의 기본 필수 PPE이다. `rules`는 작업자에게 보여 줄 안전 수칙 문구이다. 작업자 계정의 담당 구역은 이 기본 규칙을 조회하기 위한 설정이며 영상 속 사람을 계정과 연결하지 않는다.

기존 프론트의 요청·응답 필드 이름과 형태를 유지한다. 현재 저장되는 규칙은 이후 장비 등록 시에도 구역 기본값으로 사용할 수 있으므로 장비 인식 때문에 이 필드를 삭제하거나 장비별 PPE로 덮어쓰지 않는다.

## 장비 기능에서 추가할 관계

1. 상용 VLM이 장비 후보를 제시한다.
2. 관리자가 확인·수정하여 장비를 등록하고 구역에 연결한다.
3. 장비별 추가 PPE를 설정한다. 인식 API가 제시한 장비 종류나 신뢰도만으로 PPE를 자동 확정하지 않는다.
4. 카메라·작업 위치와 해당 장비를 연결한다. 같은 구역의 모든 장비 요구사항을 모든 작업자에게 일괄 적용하지 않는다.

적용 PPE는 **구역 기본 PPE ∪ 해당 촬영 위치에 적용되는 장비 PPE**로 계산한다. 장비 규칙은 기본 PPE에 항목을 추가하며 구역 전체의 기본 PPE를 해제하지 않는다. 장비가 없는 위치는 확인된 구역 기본값을 사용한다. 카메라·구역 관계나 장비 적용 범위를 확인하지 못한 경우는 빈 PPE 목록으로 취급하지 않고 미설정 상태로 구분한다.

예: 구역 기본 PPE가 `helmet`, 프레스 장비의 추가 PPE가 `vest`이면 프레스 작업 위치는 `helmet + vest`, 해당 장비가 적용되지 않는 다른 위치는 `helmet`을 사용한다.

## 구현 순서와 연결 지점

- 현재: 구역 기본 규칙 API, 작업자 계정 구역 지정, 공통 PPE 코드 검증 구현.
- 다음: 장비 등록·장비별 규칙·카메라/작업 위치 연결 및 그 설정을 읽는 정책 조회 계층 구현.
- 이후: 이벤트 후보 판단 직전에 정책을 조회하여 해당 PPE가 필수일 때만 미착용 이벤트를 생성. 생성된 이벤트에서 기존 방송 명령 흐름을 사용.

`backend/zones/policy.py`의 `combine_required_ppe`는 구역 기본값과 명시적으로 전달된 장비별 목록을 합치는 공통 함수이다. 현재 장비 DB 조회·카메라 매핑·추론 경로에는 연결하지 않았다. 향후 정책 조회 계층에서 관리자 확정 장비의 적용 범위를 결정한 후 호출한다.

현재 YOLO가 지원하는 `helmet`, `vest`와 설정 가능한 PPE 코드는 구분한다. 보안경 등을 규칙에 등록해도 지원 모델을 전달받기 전까지 자동 탐지를 약속하지 않는다. 연결 후에는 이벤트의 적용 규칙/버전을 함께 기록하여 관리자가 규칙을 바꾸더라도 발생 당시 판단 근거를 확인할 수 있도록 확장한다.

## 직접 확인할 사항

이번 조정은 API 필드 이름과 응답 구조를 바꾸지 않는다. 수동 검증 시 구역 기본 PPE 저장·조회, 허용되지 않은 코드와 중복 코드의 422 응답, 작업자 담당 구역 조회를 확인한다. 장비 등록·적용 범위 판단·이벤트 필터링은 후속 기능을 연결한 뒤 별도로 확인한다. 이번 작성 과정에서 DB 변경이나 실행 테스트는 하지 않았다.
