# 추론 통신 복구와 다중 카메라 실행

## 동작

- 일시적인 연결 실패와 HTTP 429/500/502/503/504는 프로세스를 종료하지 않고 재접속합니다. 관측 연속성·추적·로컬 클립 대기는 초기화하고, 완료한 청크의 경계는 유지합니다. 인증·권한·잘못된 요청은 기존대로 오류를 드러냅니다.
- 사전 영상과 3초 관측이 확보되면 이벤트를 먼저 등록합니다. 후행 2초를 확보한 뒤 같은 ID로 클립을 접수합니다. 재접수는 기존 서버 중복 방지를 사용합니다. 점검 모드는 이벤트를 등록하지 않습니다.
- maintenance는 생성 후 5분이 지나고 최근 5분간 업로드 활동도 없으며 미디어 행이 전혀 없는 pending 클립 요청을 `unavailable / clip_delivery_timeout`으로 정리합니다. HTTP 본문을 받기 전과 수신 중에 활동 시각을 갱신합니다. 이미 접수되었거나 처리·복구할 미디어가 있는 요청은 보존합니다. 관리자 최종 검토를 자동 확정하지 않습니다. 정리 시점은 maintenance 실행 주기에 따릅니다.
- 증거 클립 보관 프레임만 최대 307,200픽셀·15fps 이하로 줄입니다. 원본 프레임에서 탐지와 ROI 판정을 수행합니다. 원본 FPS의 정수 간격으로 샘플링하여 25fps 입력은 12.5fps로 기록합니다. 기본 버퍼는 카메라당 256MiB이며 모델·디코더·GPU 메모리는 별도입니다.

## 수동 실행

기존 VideoClient의 서버 주소·처리 node 인증 환경을 먼저 준비합니다. 개인용 토큰과 로컬 실행기 설정은 저장소에 추가하지 않습니다. 기존 단일 카메라 추론은 중지한 뒤 다음 중 한 방식만 실행합니다. 카메라 ID와 모델 경로는 실제 등록값으로 바꿉니다.

```powershell
python -m inference_worker.run_multi --camera-id CAM_A --camera-id CAM_B --model-path C:\Models\best.pt --submit-review-candidates
```

카메라별 독립 추론 프로세스와 참고 수집기 1개를 실행합니다. 같은 카메라를 다른 실행기에서 중복 실행하지 않습니다. 한 프로세스가 종료되면 나머지도 정리하고 실패를 표시합니다. Ctrl+C로 종료하면 공통 종료 신호로 디코더·클립·우선순위 lease를 정리합니다. 응답 없는 프로세스는 유예 시간 후 종료하고, 그룹 전용 임시 폴더를 정리합니다. 서버와 GPU worker를 자동으로 시작하지 않습니다.

사진 인식·교육 생성·비식별화 worker와 PPE 추론은 별도 역할입니다. 2개 프로세스는 모델도 각각 로드하므로 실제 GPU 여유와 청크 처리 지연은 두 카메라로 최종 확인해야 합니다. 이 구성 자체를 실제 다중 카메라 검증 완료로 간주하지 않습니다.

## 선택적 카메라별 제한 재시작 (W18 준비 단계)

기본값은 위의 fail-fast 동작을 유지한다. 카메라 프로세스만 제한적으로
재시작하려면 `--camera-restart-limit N --camera-restart-delay SECONDS`를 함께
지정한다. N은 카메라당 **이번 supervisor 실행 전체의** 재시작 시도 상한이고,
SECONDS는 유한한 양의 대기 시간이다. 값은 운영자가 장비 상태에 맞게 정한다.
프로세스가 한 번 살아났다고 시도 횟수를 초기화하지 않으며 무한 재시작은 없다.

- 카메라 자식 종료 후 해당 카메라만 대기·재시작하며, 살아 있는 다른 카메라와
  참고 수집기는 유지한다. 정상 종료 코드도 장기 실행의 예기치 않은 종료로 취급한다.
- 재실행 자체 실패도 시도 횟수에 포함한다. 예산 소진, 참고 수집기 종료 또는
  최초 프로세스 생성 실패는 여전히 전체 fail-fast이다.
- 공통 stop 신호나 Ctrl+C는 대기 중 재시작도 취소하고 기존 종료·terminate·kill
  정리를 수행한다. 임시 원본 폴더는 기존 supervisor 전체 수명에 속하며 종료 시 정리된다.
- 재시작은 새 모델·버퍼·추적 상태로 시작한다. 사건 연속성 복원이나 같은 사람
  재식별을 보장하지 않는다. 미완료 요청은 서버의 기존 타임아웃·복구 규약을 따른다.
- 현재 `run_multi`의 기존 `run_server` 경로에 한정되며 continuous runner를
  자동 활성화하지 않는다. 인증·설정 오류 원인을 고치지 않으므로 반복 오류는
  시도 상한 후 확인해야 한다.

모의 프로세스 회귀만 검증한 준비 옵션이다. 실제 카메라 단절/재연결, GPU 메모리
해제와 재할당, lease 정리, 원본 임시파일 정리, 운영에 적절한 상한·대기 값은
실장비 시험 전까지 완료로 간주하지 않는다. 운영 설정은 변경하지 않았다.
