# 카메라 그룹 참고 영상 수집

관리자가 등록한 카메라 그룹에서 A 카메라가 이벤트를 생성하면, 서버는 같은 그룹의 B 카메라에 `reference` 요청을 기록합니다. 수집기는 B의 위반 탐지 여부와 관계없이 같은 시간대 영상을 기존 서버 버퍼에서 확보하여 A의 이벤트에 첨부합니다. 새로운 이벤트를 생성하거나 사건을 자동 병합하지 않습니다.

## 실행

서버 PC의 프로젝트 루트에서 실행합니다. 서버 영상 수신과 별개인 프로그램이며 GPU·YOLO를 로드하지 않습니다. 처리 node로 활성화한 기존 토큰과 서버 주소를 환경에 설정해야 합니다. 비밀번호·토큰을 실행 인자나 문서에 기록하지 않습니다.

```powershell
python -m inference_worker.reference_collector
```

`--poll 1`은 요청 조회 간격이며 기본 1초입니다. `--once`는 한 차례 조회·처리 후 종료하는 점검용으로, 영상 대기 상태를 지속적으로 처리하려면 일반 실행을 사용합니다. 기존 자동 시작 설정은 변경하지 않으며 수집기도 수동 실행합니다.

PPE 판정 → 이벤트 생성은 기존 추론 실행기의 책임입니다. 이 수집기는 참고 영상만 담당하며 트리거 카메라의 클립은 기존 경로를 사용합니다. 실제 모델 후보 생성이 차단된 상태에서는 이벤트가 자동으로 생기지 않으므로 해당 연결은 별도로 완료해야 합니다.

## API와 처리

- 처리 node 전용 `GET /api/processing/reference-clip-requests`는 접수되지 않은 `pending/reference` 요청을 최대 20개 반환합니다. 일반 관리자·작업자 토큰으로 접근할 수 없습니다.
- 각 항목은 request_id, event_id, camera_id, role, 시간대가 포함된 clip_start_at·clip_end_at, epoch deadline_at을 제공합니다. 시간 구간은 사건 관찰 시작 2초 전부터 종료 2초 후까지입니다. 처리 이벤트의 DB 시각은 UTC 규칙으로 해석합니다.
- 삭제·병합된 사건 및 이미 미디어가 등록된 요청은 목록에서 제외합니다. 실패 접수에 원본이 남은 경우 기존 관리자 재처리 경로로 처리합니다.
- 수집기는 기존 영상 스트림 조회·청크 다운로드 API를 사용하고, 기존 `POST /api/processing/events/{event_id}/clip?request_id=...`로 업로드합니다. 서버는 요청에 기록된 B 카메라와 reference 역할을 적용합니다.
- 접수된 원본은 비공개로 보관되고 기존 비식별화 worker에 queued 작업이 생성됩니다. 접수 성공은 비식별화 완료가 아닙니다. ready 결과만 검토 화면에 제공됩니다.

## 누락·실패·정리

- 필요한 후속 영상이 아직 없으면 다음 조회까지 기다립니다. 요청 생성 후 30초가 지났거나 필요한 구간이 버퍼 유효기간을 벗어났는데 확보되지 않으면 `unavailable/reference_interval_unavailable`을 기록합니다.
- 빈 구간·불완전 디코딩을 정상 참고 영상으로 제공하지 않습니다. 요청 구간 20초 초과는 `reference_window_unsupported`로 명시합니다. 긴 사건을 조용히 잘라 올리지 않습니다.
- 참고 영상은 최대 640×480, 5fps로 생성합니다. 원본 프레임을 전체 보관하지 않고 순차 인코딩하며 청크 파일·임시 결과는 작업 종료 시 삭제합니다. 고화질 증거 보존용 설정이 아닌 시연용 참고 영상 설정입니다.
- 전송 응답 유실 시 요청이 received인지 확인합니다. 미확정 전송은 다음 조회로 넘기며, 이미 접수 중인 자료는 다시 덮어쓰거나 unavailable로 바꾸지 않습니다. 404·409·통신 오류 하나가 다른 참고 요청 처리를 중단하지 않습니다.
- 수집기가 꺼져 있으면 pending 요청은 자동으로 완료되지 않습니다. 다시 실행하면 확보 가능한 자료를 수집하고, 불가능한 자료는 위 기준으로 종료합니다. 강제 종료 시 임시 파일 정리는 보장되지 않으므로 일반 종료를 사용합니다.

## 검증

합성 MP4의 구간 조립·프레임 수·임시 파일 정리, 누락 구간, 카메라 미연결 대기·시간 초과, 긴 구간, 개별 요청 장애 격리, API 권한·삭제 제외·접수 중 실패 보고 차단을 검증합니다. 테스트용 FastAPI와 HTTP 클라이언트로 A 사건의 B 참고 미디어 접수 → 가짜 비식별 결과 게시 → 중복 조회 시 추가 생성 없음도 확인합니다. 실제 얼굴 탐지 정확도·2대 실 카메라·실제 GPU는 별도 통합 검증 대상입니다.
