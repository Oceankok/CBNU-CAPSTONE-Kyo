# 연속 영상 추론의 대기 시간 분리

## 확인한 문제

1초 조각을 분석한 뒤 기본 poll 값인 1초를 추가 대기하여 분석·통신 시간이 매 조각마다 누적됐습니다. 실제 두 카메라 점검에서 정상 수신 채널도 오래 실행하면 조각 만료와 클립 초기화가 발생했습니다. 다른 채널의 송신 중단과 이 처리 지연은 구분합니다.

## 수정 범위

- 새 영상이 없거나 스트림·정책을 기다릴 때는 기존 poll 대기를 유지합니다.
- 조각 처리 후에는 추론 우선 신호를 해제하고 최대 0.1초만 양보합니다. 데이터가 쌓였을 때 1초씩 추가로 쉬지 않습니다.
- 판정 모델·신뢰도·ROI·관측 시간·클립 완전성 검사·서버 보관 기한은 변경하지 않습니다.

## 격리 재현

가짜 시계로 1초 조각을 240개 공급하고 조각당 분석 250ms와 HTTP/lease 비용, 서버 30초 만료를 모사합니다. 수정 전 테스트 실패를 확인한 뒤 동일 조건에서 만료 없이 순서대로 처리하고 사전·관측·후행 구간의 클립을 전달하는지 확인합니다. 입력이 없을 때는 쉬고, 처리 후 양보 중에는 GPU lease가 해제되어 있는지도 확인합니다.

이 결과는 실제 GPU 처리량이나 두 카메라에서 비식별화가 충분히 진행된다는 실측 결과가 아닙니다. 병합·서버/호스트 버전 반영 후 실제 두 채널을 장시간 실행하여 조각 나이·만료·클립 완성·비식별화 대기와 한쪽 단절 후 정상 채널 진행을 다시 확인합니다. 부족하면 실제 분석·인코딩·통신 시간을 측정해 다음 병목을 구분합니다.
