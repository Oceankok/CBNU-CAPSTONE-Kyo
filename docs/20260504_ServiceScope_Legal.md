## 1. 서비스 목적 재정의

### 1-1. 변경 배경

기존 설계(`20260407_PPE.md`)는 시스템의 1차 목적을 **"분기별 PPE 미준수 경향 분석 및 교육 추천"**으로 정의하였다.

검토 결과, 본 서비스는 실제로 보호구 착용 의무 구역에서 PPE 미착용 상황을 인지하여 **즉시 시정 알림을 제공**하는 역할을 겸하므로, 이를 1차 목적으로 명확히 설정할 필요가 있다.

### 1-2. 확정된 목적 계층

| 계층 | 목적 | 설명 |
|---|---|---|
| **1차 목적** | 안전 확보 및 산업재해 예방 | PPE 미착용 상황을 즉시 인지하여 현장 담당자에게 시정 알림 제공 |
| **2차 목적** | 분기별 경향 분석 및 교육 추천 | 확정 위반 데이터를 누적하여 교육 우선순위 도출 |

### 1-3. 명확히 제외되는 목적

다음 목적으로 설계하거나 운영하는 것은 **금지**한다.

- 인사평가 반영
- 상시 감시 체계 구축
- 자동 징계 시스템

## 2. 법적 근거 및 준수 의무

### 2-1. 적용 법령

| 법령 | 관련 항목 |
|---|---|
| 산업안전보건법 | 근로자는 사업주의 안전조치를 준수할 의무가 있음 |
| 산업안전보건기준에 관한 규칙 | 사업주는 보호구를 지급·관리하고, 근로자가 지급된 보호구를 착용하도록 규정 |
| 개인정보 보호법 | 개인정보의 수집·이용과 목적 외 이용을 엄격히 제한 |
| 근로기준법 제94조 | 취업규칙 작성·변경 시 근로자 과반수 의견 청취 필요; 불리한 변경 시 동의 필요 |

### 2-2. 주요 법적 리스크

1. **개인정보 처리 리스크**
   - 실시간 알림을 위해 특정 시점의 근로자를 식별하게 되므로, 영상 저장을 하지 않더라도 개인정보 처리 이슈가 완전히 사라지지 않는다.
   - 개인별 위반 이력을 장기 보관하거나 다른 목적으로 재사용하는 구조는 법적 리스크를 높인다.
   - 형식상 이름이 없더라도 근무표나 출입기록 등 다른 정보와 결합해 특정인을 알아볼 수 있으면 개인정보로 평가될 수 있다.

2. **CCTV 설치 위치 리스크**
   - 개인정보보호위원회 안내에 따르면 공개된 장소의 CCTV는 범죄 예방, 시설 안전, 화재 예방 등 법이 정한 목적 범위에서 설치·운영 가능하다.
   - 사무실 내부 등 비공개 장소에 설치하는 경우에는 **근로자 동의**가 필요하다.
   - 화장실, 탈의실 등 사생활 침해 우려 장소에는 설치가 **금지**된다.

3. **징계 연결 리스크**
   - 서비스 결과를 징계·평가와 직접 연결하려면 취업규칙 정비와 근로자 과반수 동의가 필요하다.
   - 안전 시정 알림 체계를 사실상 제재 체계로 확장할 경우 별도의 절차적 정당성 확보가 필요하다.

## 3. 설계 원칙

### 3-1. 적용 범위 한정

- 본 서비스는 **PPE 착용 의무가 있는 위험구역 및 작업구역**으로 적용 범위를 한정한다.
- 설치 목적, 설치 장소, 관리책임자 등을 명확히 고지하는 방식으로 운영한다.

| 설치 가능 | 설치 주의 | 설치 금지 |
|---|---|---|
| 프레스 구역, 절삭/가공 구역 등 위험구역 | 사무실 내부 (근로자 동의 필요) | 화장실, 탈의실 |
| 자재 이동 구역 등 안전관리 목적 명확한 구역 | 비공개 장소 일반 | 사생활 침해 우려 장소 |

### 3-2. 데이터 최소화 원칙

5월 초안은 "원본 영상 저장 안 함"을 전제로 했으나, 실제 구현은 비식별화와 재시도를 위해 **기간을 제한한 비공개 임시 보관**을 둔다. 문서와 구현이 어긋나지 않도록 아래와 같이 정리한다.

| 항목 | 원칙 | 현재 구현 |
|---|---|---|
| 연속 영상(현장 PC → 서버) | 추론에 필요한 최소 시간만 보관 | 약 1초 MP4 조각을 서버 비공개 폴더에 **30초 버퍼**로 보관, 카메라당 64MiB·전체 256MiB 상한, 만료 시 정리 |
| 이벤트 원본 클립 | 비식별화 실패 시 재처리에 필요한 기간만 보관 | 이벤트 전후 약 2초 클립을 비공개 저장, 기본 **24시간 후 정리**(`PPE_MEDIA_SOURCE_TTL_SECONDS`). 원본 경로·URL은 어떤 화면·API에도 노출하지 않음 |
| 검토·보관용 이미지·영상 | **얼굴 비식별화를 거친 결과만** 저장·표시 | 서버 GPU worker가 얼굴을 가린 결과만 검토 화면에 제공. 처리 전·실패 자료는 표시하지 않음 |
| 이름, 사번 등 직접 식별자 | 수집 안 함 | 영상 속 사람과 로그인 계정을 연결하지 않음. 탐지 `tracking_id`는 한 카메라 안에서 위반 지속을 판단하는 임시 번호이며 사람의 신원이 아님 |
| 이벤트 기록 | 검토 후 보관·삭제 결정, 최소 기록만 유지 | 검토 후 보관(동의 필요) 또는 삭제를 선택. 삭제해도 이벤트·검토·삭제 이력의 최소 기록은 유지 |
| 집계 기록 | 구역·PPE 기준 집계 중심 | 분기 통계와 교육 추천은 구역·PPE 단위. 작업자 화면에는 점수·위반 건수를 보여 주지 않음 |

> **재식별 방지**: 기록은 근무표, 출입기록 등 다른 정보와 결합해도 특정인을 알아볼 수 없도록 최소화한다. 다만 얼굴 비식별화는 탐지 누락이 있을 수 있어 완전한 익명화를 보장하지 않는다(3-6).

### 3-3. 징계·평가 분리 원칙

- 본 서비스에서 발생한 알림이나 집계 정보를 **징계·평가와 직접 연결하지 않는다.**
- 구현상 영상 속 사람과 로그인 계정을 자동으로 연결하거나 개인별 평가 점수를 산출하는 기능은 없다. 작업자 계정은 **구역 배정과 권한**에만 쓰인다.
- 만약 서비스 운영 결과를 불이익 조치에 활용하려면 취업규칙 정비와 별도 절차가 필요하며, 본 시스템의 범위 밖이다.

### 3-4. 데이터 흐름과 보관 위치

| 단계 | 처리 | 어디에 | 얼마나 |
|---|---|---|---|
| ① 영상 송출 | 현장 PC가 카메라 영상을 약 1초 MP4로 나누어 서버에 전송(인증된 현장 PC만) | 현장 PC → 서버 | 전송 후 현장 PC의 조각 파일 삭제 |
| ② 서버 버퍼 | 추론용으로 조각을 수신·보관 | 서버 비공개 폴더 | 30초, 상한 초과 시 오래된 것부터 정리 |
| ③ 추론 | 서버 GPU에서 사람·PPE 탐지, 위반이 일정 시간 지속되면 후보 이벤트 생성 | 서버 | 판정 결과(시각·카메라·구역·신뢰도)만 DB에 기록 |
| ④ 이벤트 클립 | 이벤트 전후 약 2초 클립을 만들어 서버에 업로드 | 서버 비공개 폴더 | 원본은 기본 24시간 |
| ⑤ 비식별화 | 호스트 GPU worker가 얼굴을 가린 결과를 생성하고 서버가 검증·게시 | 서버 처리 결과 볼륨 | 삭제·취소된 건의 늦은 결과는 게시하지 않음 |
| ⑥ 관리자 검토 | 비식별 이미지·영상으로 확정/오탐/보류/검토 불가 판단 | 관리자 화면(로그인·미디어 쿠키 필요) | 검토 담당자는 로그인 정보에서 기록 |
| ⑦ 보관·삭제 | 동의 확인된 자료만 보관, 그 외 삭제. 동의 철회 시 삭제로 전환 | 서버 | 보관 종료 시각까지. 파일 삭제 실패는 재시도 |
| ⑧ 방송·알림 | 현장 PC 스피커 방송, 관리자 화면 알림(20초 주기 조회) | 현장 PC, 관리자 화면 | 영상 없이 텍스트·음성 명령만 전달 |
| ⑨ 백업 | DB와 보관 완료 미디어를 백업(카메라 원본·로그인 자격 증명 제외) | 접근을 제한한 위치 | 기존 만료 정책 적용 |

### 3-5. 외부로 나가는 데이터

| 대상 | 보내는 것 | 조건 |
|---|---|---|

### 3-6. 한계

- 얼굴 탐지에 누락이 있을 수 있어 **완전한 익명화를 보장하지 않는다.** 검토 화면에 이를 안내하고, 검토자는 화면 전체를 확인한다.
- 얼굴을 가려도 체형·작업복·위치로 개인이 추정될 수 있다. 구역·시간 등 다른 정보와 결합하면 재식별 위험이 남는다.
- AI의 탐지 정확도는 아직 충분히 검증되지 않았다. 자동 판정은 안전모·안전조끼 중심이며, 그 외 PPE는 작업자 안내용이다.
- PDF 동의서의 구조만 검사하며 서명·내용의 적절성·법적 유효성은 판정하지 않는다. 적용 범위는 관리자가 매번 확인한다.

### 3-7. 동의, 보관, 학습 사용, 철회

1. 관리자가 검토를 마친(확정·오탐) 이벤트에 대해 **작업자의 모델 개선용 이용 동의서(PDF)** 를 등록하고, 사업장 코드·양식 버전·적용 범위를 기록하며 적용 대상임을 직접 확인한다.
2. 동의서 기록을 이벤트의 보관 결정에 연결하고 **보관 종료 시각**을 정한다. 동의가 없으면 자료를 삭제한다.
3. 동의서를 철회하면 해당 동의서로 보관 중이던 이벤트의 이미지·영상이 삭제 대상으로 바뀌고 기존 삭제·재시도 경로로 정리된다. 이벤트·검토·동의 기록·최소 감사 이력은 남는다.
4. **보관한 자료를 모델 학습에 자동으로 사용하는 기능은 구현하지 않았다.** 학습에 쓰는 경우의 절차와, 이미 학습된 모델에 대한 철회 처리는 정해지지 않았다(팀·법무 확인 필요).

## 5. 캡스톤 적용 범위

본 프로젝트는 실제 서비스 배포가 아닌 **시스템 시연 및 개념 검증** 수준이다. 5월에는 생략하기로 했던 항목 중 일부는 구현되었고, 나머지는 실제 도입 시 별도 검토가 필요하다.

| 항목 | 현재 상태 | 실제 도입 시 필요 |
|---|---|---|
| 로그인/인증 | **구현**: JWT, Argon2, 관리자/작업자 역할, 계정 비활성·로그아웃 | 비밀번호 정책, 접근 기록 점검 |
| 영상 원본 삭제 정책 | **구현**: 30초 버퍼·24시간 원본 정리·보관/삭제 결정·maintenance 정리 | 보관 기간 확정, 운영 중 삭제 감사 |
| 동의 절차 | **구현**: 동의서 PDF 등록·보관 연결·철회 | 동의서 양식·적용 대상·이용 목적의 법무 검토 |
| 고지 문안 (CCTV 설치 고지) | 해당 없음 | 사내 고지 문안, 개인정보 처리방침 작성 필요 |
| 취업규칙 정합성 검토 | 해당 없음 | 법무 검토 필요 |
| 외부 전송 | 시연용 Cloudflare 터널, 선택적 외부 AI(기본 비활성) | 내부망/VPN 전환, 외부 AI 사용 범위 계약·고지 |
| 배포 환경 | 서버 PC에서 Docker Compose를 수동으로 실행(필요할 때만 시작) | 사내 인트라넷 또는 VPN 기반 내부망 |

## 6. 아키텍처 현황

| 계층 | 현재 | 비고 |
|---|---|---|
| 프론트엔드 | **React + TypeScript (Vite)**, 하나의 앱에서 관리자/작업자 역할별 화면 | 모바일 반응형(≤768px 하단 탭), 배포 시 nginx 웹 컨테이너 |
| 백엔드/API | **FastAPI** | 현장 PC·처리 worker는 별도 node 토큰으로 인증 |
| 데이터베이스 | **PostgreSQL**(서버·시연), SQLite(로컬 개발·테스트) | 버전별 마이그레이션 적용 |
| AI 처리 | 서버 GPU(YOLO 추론, SCRFD/YuNet 얼굴 비식별화) | 호스트 worker가 컨테이너 밖에서 실행 |
| 서비스 형태 | 웹 대시보드(관리자) + 작업자 모바일 화면 + 현장 PC 방송 프로그램 | 별도 모바일 앱 없음 |
| 알림 | 관리자 화면 20초 주기 조회(뱃지·토스트), 현장 PC 음성 방송 | WebSocket/SSE는 미구현 |
| 배포 | Docker Compose, GHCR 이미지 게시, production 승인 배포 워크플로 | 자동 배포용 runner 등록은 미완료 |
| 프론트↔백 통신 | 같은 출처 `/api`(개발은 Vite 프록시, 배포는 nginx) | `VITE_API_BASE_URL`로 변경 가능 |

## 7. 팀·법무 확인이 필요한 사항

이 문서는 구현 사실을 기준으로 정리한 것이며 법적 판단을 대신하지 않는다. 아래는 결정이 필요하다.

1. 원본 영상 임시 보관(30초 버퍼, 24시간)이 개인정보 처리방침과 고지에서 어떻게 설명되어야 하는지
2. 시연에서 원본 영상이 Cloudflare를 경유하는 구성을 허용할지, 내부망으로 대체할지 (#152, #154)
3. 장비 사진 분석에 구독 계정 기반 외부 AI를 쓸지 (#145)
4. 모델 개선·학습 사용에 대한 동의서 양식, 적용 대상, 철회 시 이미 학습된 모델의 처리
5. 보관 기간과 `reviewer_id` 등 최소 기록의 보존 기간

## 부록 — 이 문서가 적용되는 설계 원칙 요약

아래 4가지 원칙이 시스템 전체 설계에 걸쳐 일관되게 적용되어야 한다.

1. **적용 범위 한정** — PPE 착용 의무가 있는 위험구역으로 적용 범위 한정
2. **데이터 최소화** — 얼굴 비식별화 후에만 저장·표시하고, 원본은 기간을 제한해 비공개로만 보관, 재식별 방지 설계
3. **집계 중심 기록** — 이벤트 기록은 최소화하고 교육 추천은 구역·PPE 집계 기준
4. **징계·평가 분리** — 인사·징계 목적과 명확히 분리하여 운영, 영상 속 사람과 계정을 연결하지 않음
