# GPU worker 실제 연동 검증

2026-10-13 별도 Docker API·PostgreSQL과 서버 PC의 네이티브 worker를 실제 HTTP로 연결하여 SCRFD CUDA 처리를 검증했습니다. 테스트 소스는 이전에 제공된 `8965389-hd_1280_720_25fps.mp4`의 약 1초 시점 이미지와 이후 3초 클립입니다. 외부 VLM 전송·방송·실시간 PPE 추론은 실행하지 않았습니다.

단일 실행 수치이며 worker 프로세스마다 모델을 새로 로드했습니다. 지속 실행·동시 추론 부하에서의 성능 수치가 아닙니다. 영역 누적은 인원수가 아닙니다.

다음 흐름이 통과했습니다.

1. 관리자 인증 후 원본 접수 및 queued 상태 확인
2. 처리 권한 node의 작업 수신·인증된 원본 다운로드
3. 실제 SCRFD 모델·CUDA 추론 및 결과 업로드
4. ready/complete 게시와 관리자 미디어 다운로드
5. worker 로컬 원본·결과·journal·lock 정리와 서버 cleanup 확인
6. 처리 영상 전체 75프레임 디코딩
7. 비식별 자료가 있는 테스트 이벤트에 검토 값 저장 — 실제 PPE 위반 판정은 아닙니다.
8. delete 결정·삭제 완료·미디어 URL 차단

처리 이미지와 영상 표본 프레임을 시각적으로 확인하여 얼굴 모자이크를 확인했습니다. 전체 영상의 모든 상황·사람·얼굴 각도에 대한 정확도 검증은 아닙니다. PPE 추론·현장 영상 송신·방송까지의 통합 검증도 이번 범위에 포함하지 않습니다.

## 발견 및 수정

첫 실행에서 GPU 처리는 완료됐지만 API의 결과 게시가 500으로 실패했습니다. Docker의 `.private_media`와 `storage`가 서로 다른 volume이어서 `os.replace`가 `Invalid cross-device link`를 반환했습니다.

게시 파일을 결과 저장소 안의 임시 파일에 복사한 뒤 동일 volume에서 원자적으로 교체하도록 수정했습니다. 기존 로컬 미디어 게시에도 같은 함수를 적용했으며, 중단 후 남은 staging 파일을 maintenance가 정리하도록 했습니다. 동일 filesystem에서만 rename이 가능한 상황을 재현하는 회귀 테스트를 추가했습니다.

실패 보고 중 끊어진 HTTP 연결에 대해서는 한 번 추가 전송을 시도하도록 보완했습니다. 이후 새 테스트 프로젝트에서 이미지·영상·삭제 연동을 모두 통과했습니다.

수정 후 관련 작업 테스트 8개가 통과했습니다. 백엔드 전체 회귀는 SQLite·PostgreSQL 각각 84개 중 80개 통과, DB 종류별 전용 테스트 4개 제외로 확인했습니다.

## 자료 및 정리

입력·결과·표본 프레임·측정 결과·실행 로그는 Git 제외 경로 `test_images/gpu-worker-validation/`에 보관했습니다. 원본 다운로드 파일은 변경하지 않았습니다. 실물 검증용 API·PostgreSQL 컨테이너와 volume은 종료 후 제거했고, 네이티브 worker도 종료했습니다. 기존 개발 DB·미디어·구독 자격 증명은 사용하거나 변경하지 않았습니다.

테스트용 로컬 결과 사본은 확인을 위해 유지하며, 이것은 API 내부 이벤트 미디어의 삭제 여부와 별개의 검증 자료입니다. Docker 이미지·빌드 캐시는 재사용을 위해 유지했습니다.
